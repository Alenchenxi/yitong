## 验收标准（AC）

### AC1 发布附位置

When 提交帖子成功
Then AnonymousPost 落 `location_city`/`location_district`（市/区官方名文本，无任何坐标字段），树洞列表卡、广场混合流匿名卡、详情页显示 📍市·区

### AC2 不选位置
Given 用户不点选点或地图中取消
When 提交帖子成功
Then `location_city`/`location_district` 为 null，所有展示面不渲染位置 chip

### AC3 直辖市解析
Given 选点地址含「北京市朝阳区」式文本
When 服务端解析
Then city=北京市、district=朝阳区（直辖市走省表补位逻辑，与 listDistricts 口径一致）

### AC4 区县无法解析
Given 地址文本命中城市但无区县命中
When 服务端解析
Then district=null、city 正常落库，展示面仅显示市

### AC5 图片审核限制友好提示
Given 上传图片经服务端规范化后仍 >1MB
When 发帖（树洞或表白墙，同函数）
Then 报 90003「图片过大，无法完成安全审核，请更换图片后重试」；webp 等不可解码格式报 90003「图片格式不支持安全审核，请更换图片后重试」（确定性拒绝，直抛不区分环境，同 90002 口径；下载失败/微信接口失败等瞬态仍走原不可用口径）

### AC6 回归

## 风险与注记
1. 地址文本解析市/区依赖静态表 + needle 匹配，跨市同名街区可能误判市级（parseCityFromAddress 已知限制，选点地址含省/市前缀时基本可避免）——wx.chooseLocation 返回的 address 通常含「省市区」全前缀，风险低
2. GIF 上传：jimp 可读 GIF 但重编码取首帧（动图审核只审首帧）——可接受，登记不改
3. webp：jimp 0.22 不可解码 → 走 AC5 格式文案拒绝（upload 侧允许 webp 的口径与审核侧不一致，若实测 webp 占比高，P3-08 mediaCheckAsync 迁移一并解决）
4. mediaCheckAsync（P3-08）暂缓：启动前需用户确认「先发后审」语义 + 操作小程序后台消息推送配置
