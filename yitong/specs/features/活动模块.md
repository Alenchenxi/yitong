# 活动模块 - 功能需求说明书

> 状态：已确认  
> 确认日期：2026-11-10  
> 适用产品：燚桐校园生活小程序  
> 说明：本模块是具备发布、报名和参与管理能力的“活动报名”模块，与现有表白墙“活动专题”内容聚合功能并存，二者互不替代。

## 1. 背景与价值

**为什么做**：平台和圈子目前缺少完整的活动发布、报名、沟通及提醒闭环。活动信息只能通过普通内容传播，无法收集自定义报名资料、管理人数和候补、建立参与人群聊，也无法把报名资料同步至外部协作工具。

**做成什么样**：平台管理员和圈子管理员可以按权限发布活动，用户可以发现、关注、报名并进入活动群聊，活动管理者可以完成审核、候补、提醒、取消资格及飞书同步等全流程管理。

**关联模块**：圈子、广场、用户角色与管理员权限、群聊、站内通知、微信订阅消息、飞书多维表格。

## 2. 范围

### 2.1 本次做

- 新增独立活动板块，并在用户端底部导航增加“活动”，形成 6 个固定入口。
- 广场内容分类增加“活动”。
- 平台管理员发布全圈可见活动。
- 圈子管理员向自己管理的单个圈子发布活动。
- 活动草稿、发布、报名、候补、进行、结束、取消和下架管理。
- 直接报名和管理员审核两种报名方式，每个活动选择其中一种。
- 可配置人数上限、自动候补队列和自动转正。
- 自定义报名表单及报名资料复审。
- 活动发起人和多名活动管理员协作管理。
- 活动群聊及活动结束后的群聊只读规则。
- 每次冷启动的活动上新轮播弹窗。
- 感兴趣、不感兴趣及我的活动管理。
- 活动开始前三天、前一天自动提醒，以及受频率限制的手动提醒。
- 可复用飞书连接及飞书多维表格单向同步。
- 活动介绍中的链接识别、高亮和跳转。

### 2.2 本次不做

- 收费活动、支付、退款、优惠及票种。
- 活动签到、二维码核销和到场人数统计。
- 候补转正后的限时人工确认，候补统一自动转正。
- 活动发起人与参与人的活动专属一对一私聊。
- 普通飞书文档、飞书电子表格及其他云文档同步。
- 将现有表白墙“活动专题”迁移或替换为本活动模块。

## 4. 需求详述

### 4.1 核心流程

1. 平台管理员或圈子管理员创建活动，填写活动信息、报名规则、自定义表单、活动管理员和可选的飞书同步配置。
2. 管理员发布活动，平台活动对所有圈子可见，圈子活动仅对指定圈子可见。
3. 用户通过底部“活动”、广场活动分类、活动分享或冷启动上新弹窗查看活动。
4. 用户可以标记感兴趣、不感兴趣，或提交报名表。
5. 系统根据活动配置执行直接报名或管理员审核；名额已满时进入候补队列。
6. 报名成功用户占用正式名额并自动加入活动群聊，候补用户不加入群聊。
7. 名额释放时，候补队列首位自动转正、加入群聊并收到通知。
8. 活动开始前三天和前一天执行自动提醒，发起人和活动管理员也可受限地手动提醒。
9. 报名新增、修改、取消及活动取消等变化同步到活动绑定的飞书多维表格。
10. 活动正常结束后群聊继续开放 7 天再转为只读；活动取消时群聊立即转为只读。

### 4.2 活动字段

| 字段 | 规则 |
|------|------|
| 活动名称 | 必填，需通过内容安全检查 |
| 活动首图 | 必填，用于列表、详情和上新弹窗 |
| 活动介绍 | 必填，支持安全链接识别、高亮和点击 |
| 活动形式 | 必填，线下、线上、线上线下结合三选一 |
| 活动地点 | 线下或线上线下结合时必填 |
| 参与方式或链接 | 线上或线上线下结合时必填 |
| 地点和参与链接可见性 | 可选公开，或仅正式报名成功用户可见 |
| 活动时间 | 可选；未填写时为长期活动，不执行相对开始时间提醒 |
| 报名开始时间 | 可选；未填写时随活动发布开放报名 |
| 报名截止时间 | 可选；有活动开始时间时默认不晚于活动开始，无活动时间时可长期报名 |
| 报名方式 | 必填，直接报名或管理员审核，每个活动只能选择一种 |
| 人数上限 | 可选；未填写时不限人数 |
| 正式报名人数 | 自动统计，仅计算报名成功用户 |
| 待审核人数 | 自动统计，与正式报名人数分开显示 |
| 候补人数 | 自动统计，与正式报名人数分开显示 |
| 自定义报名表单 | 可配置字段类型、必填、提示文字、选项和顺序 |
| 活动发起人 | 自动记录创建活动的管理员，可按权限转让 |
| 活动管理员 | 可配置多人 |
| 所属范围 | 平台活动为全部圈子；圈子活动为一个指定圈子 |
| 飞书同步配置 | 可选，选择发起人已有连接及目标多维表格 |
| 创建时间 | 自动记录，不可手工修改 |
| 更新时间 | 活动信息变更时自动刷新 |
| 活动状态 | 草稿、报名中、待开始、进行中、已结束、已取消、已下架 |

### 4.3 自定义报名表单

- 支持单行文本、多行文本、单选、多选、日期、手机号、微信号和图片上传。
- 每个字段可设置必填或选填、提示文字、选项和展示顺序。
- 产生第一条报名后锁定表单结构，不允许删除字段、改变字段类型或改变选项含义。
- 产生报名后仍可修改字段说明、调整展示顺序和新增选填字段。
- 普通用户只能查看自己的报名资料。
- 活动发起人、活动管理员和平台管理员可以查看报名资料。

### 4.4 报名、审核与候补

- 直接报名型活动在资料校验通过且有名额时立即成功。
- 审核型活动提交后进入待审核，审核通过后才成为正式参与人。
- 正式名额已满时，直接报名用户进入候补；审核型用户审核通过后进入候补。
- 候补按进入候补队列的时间先后排序。
- 正式名额释放后，候补第一名自动转正，无需用户再次确认。
- 候补转正后自动加入活动群聊并收到站内通知；满足条件时同时发送微信订阅消息。
- 用户主动取消正式报名后释放名额、退出群聊，并可在报名截止前重新报名。
- 用户可以主动退出候补队列。
- 被管理员取消资格的用户不得再次报名或进入候补队列。
- 尚未审核的报名修改后继续保持待审核。
- 已审核通过用户修改资料时保留正式资格、名额和群聊身份，新资料进入复审。
- 新资料复审被拒时恢复上一次审核通过的资料，不直接取消活动资格。

### 4.5 活动群聊

- 每个活动对应一个活动群聊。
- 正式报名成功或候补自动转正后自动加入群聊。
- 待审核和候补用户不加入群聊。
- 用户主动取消报名或被管理员取消资格后退出群聊。
- 活动发起人和活动管理员拥有活动群聊管理权限。
- 活动正常结束后群聊继续开放 7 天，之后自动转为只读并保留历史记录。
- 活动取消后群聊立即转为只读并保留历史记录。

### 4.6 上新弹窗与兴趣状态

- 每次冷启动检查并展示一次活动上新弹窗，前后台切换不重复触发。
- 弹窗候选范围为平台活动和用户当前圈子的活动。
- 弹窗按发布时间倒序展示最多 5 个最新符合条件的活动。
- 每项展示活动首图、活动名称、活动简介、活动时间、“查看详情”和报名相关按钮。
- 用户可以对每个活动选择“感兴趣”或“不感兴趣”。
- 感兴趣活动进入“我的活动-感兴趣”，但不占用名额、不加入群聊、不接收参与提醒。
- 不感兴趣活动不再进入该用户后续的上新弹窗。
- 用户可以在“不感兴趣”列表恢复活动，误操作后提供即时撤销。
- 已报名活动仍可展示，主操作改为“查看报名”。
- 已满活动仍可展示，主操作显示“名额已满”。
- 已取消、已下架和已结束活动不进入弹窗。
- 过滤后没有可展示活动时不弹出空弹窗。

### 4.7 通知与提醒

- 报名成功、审核结果、候补转正、参与资格取消、活动重要信息变更和活动取消均生成站内通知。
- 设置活动开始时间后，在开始前三天和前一天向正式参与人执行自动提醒。
- 发布活动时距离开始不足三天，只执行尚未错过的提醒节点。
- 未填写活动时间时不执行前三天和前一天提醒。
- 微信订阅消息只有在配置模板且用户主动授权时发送。
- 未配置模板或用户未授权时不发送微信消息，但站内通知不受影响。
- 发起人和活动管理员可选择全部正式参与人或指定参与人发送固定手动提醒。
- 候补用户不接收“参加活动”手动提醒。
- 同一活动对同一用户每 24 小时最多手动提醒一次。
- 手动提醒记录发送人、时间、对象和结果。

### 4.8 飞书同步

- 发起人先创建可复用的飞书连接，再由活动选择连接和目标多维表格。
- 第一版只支持飞书多维表格。
- 连接密钥始终脱敏展示，只有活动发起人可以管理活动所用连接。
- 新报名、报名资料修改、用户主动取消、管理员取消资格和活动取消均触发同步。
- 每条报名使用稳定标识，重试不得在目标表格生成重复记录。
- 同步状态至少包含待同步、同步成功和同步失败。
- 同步失败不影响小程序内报名结果。
- 活动发起人和活动管理员可以查看同步状态、失败原因并手动重试。

### 4.9 交互规则

- 发布、报名、审核、取消活动和取消参与资格等提交操作需防止重复点击。
- 取消整个活动、取消参与资格和退出报名需二次确认。
- 管理员取消参与资格时必须填写原因，并通知用户。
- 活动介绍中的合法链接需高亮；无法直接打开时提示用户并支持复制链接。
- 用户退出或切换圈子后，已报名活动继续在“我的活动”中可访问。
- 已报名用户退出原圈子后不再从新圈子的活动列表和上新弹窗看到原活动，但报名详情和群聊保持可用。

### 4.10 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 平台管理员发布的活动固定对全部圈子可见，后续新建圈子也可见 |
| BR-002 | 圈子管理员只能向自己管理的一个圈子发布活动，默认选择当前圈子 |
| BR-003 | 每个活动只能选择直接报名或管理员审核中的一种报名方式 |
| BR-004 | 正式报名人数、待审核人数和候补人数必须分别统计 |
| BR-005 | 候补严格按进入队列时间排序，名额释放后自动转正第一名 |
| BR-006 | 被管理员取消资格的用户不能再次报名同一活动 |
| BR-007 | 感兴趣不等于报名，不占名额、不加入群聊、不触发参与提醒 |
| BR-008 | 不感兴趣活动不再进入该用户的上新弹窗，除非用户主动恢复 |
| BR-009 | 只有活动发起人可以转让发起人、取消整个活动、增删活动管理员及管理飞书连接 |
| BR-010 | 活动管理员可编辑活动、审核报名、管理候补和群聊、取消参与资格、提醒用户及查看同步状态 |
| BR-011 | 同一活动对同一用户每 24 小时最多手动提醒一次 |
| BR-012 | 有报名记录的活动不得彻底删除，只能取消或下架并保留记录 |
| BR-013 | 飞书同步失败不得导致小程序内报名失败 |
| BR-014 | 第一版活动全部免费，不提供支付、退款、票种、签到或核销能力 |
| BR-015 | 现有表白墙“活动专题”与本活动报名模块是两个独立功能 |

## 5. 验收标准

### 5.1 正常流程（Happy Path）

- [ ] **AC-001：六项底部导航**
  - **Given** 用户以普通用户身份进入小程序
  - **When** 查看底部导航
  - **Then** 展示“广场、表白墙、树洞、兼职、活动、我的”6 个入口，活动入口的视觉和选中行为与现有入口一致

- [ ] **AC-002：广场活动分类**
  - **Given** 用户进入广场
  - **When** 查看内容分类并选择“活动”
  - **Then** 进入当前可见范围内的活动列表，并可打开活动详情

- [ ] **AC-003：平台活动发布**
  - **Given** 平台管理员已填写合法的活动信息
  - **When** 发布活动
  - **Then** 发布成功，当前及后续新增的所有圈子用户均可查看该活动

- [ ] **AC-004：圈子活动发布**
  - **Given** 圈子管理员至少管理一个圈子
  - **When** 创建活动并选择发布圈子
  - **Then** 只能选择自己管理的一个圈子，页面默认选择当前圈子，发布后仅该圈子范围可见

- [ ] **AC-005：活动配置完整保存**
  - **Given** 管理员正在创建活动
  - **When** 填写名称、首图、介绍、活动形式、相应地点或参与方式及报名配置并保存
  - **Then** 活动保存成功，创建时间自动记录，后续编辑时更新时间自动刷新

- [ ] **AC-006：自定义报名表单**
  - **Given** 发起人正在配置尚未产生报名的活动
  - **When** 添加支持类型的字段并设置必填、提示、选项和顺序
  - **Then** 报名页按所配置的结构展示，并在提交时校验必填内容

- [ ] **AC-007：直接报名成功**
  - **Given** 活动采用直接报名、仍有名额且用户填写内容有效
  - **When** 用户提交报名
  - **Then** 立即显示报名成功，正式报名人数增加 1，用户自动加入活动群聊

- [ ] **AC-008：审核型报名成功**
  - **Given** 活动采用管理员审核且用户已提交有效报名
  - **When** 活动管理员审核通过
  - **Then** 报名状态变为成功，正式报名人数增加 1，用户自动加入活动群聊并收到通知

- [ ] **AC-009：满员进入候补**
  - **Given** 活动已达到人数上限
  - **When** 直接报名用户提交成功，或审核型用户被审核通过
  - **Then** 用户按当前时间进入候补队列，不占正式名额且不加入活动群聊

- [ ] **AC-010：候补自动转正**
  - **Given** 活动有候补用户且释放了一个正式名额
  - **When** 系统处理名额变化
  - **Then** 候补第一名自动转为报名成功、占用名额、加入群聊并收到通知

- [ ] **AC-011：标记感兴趣**
  - **Given** 用户尚未报名某活动
  - **When** 选择“感兴趣”
  - **Then** 活动进入“我的活动-感兴趣”，不占名额、不加入群聊且不接收参与提醒

- [ ] **AC-012：冷启动活动弹窗**
  - **Given** 小程序冷启动且存在用户可见的有效活动
  - **When** 系统完成活动检查
  - **Then** 按发布时间倒序展示最多 5 个最新活动，并显示首图、简介、详情和报名操作

- [ ] **AC-013：不感兴趣过滤**
  - **Given** 用户在活动上新弹窗或详情中选择“不感兴趣”
  - **When** 用户后续再次冷启动小程序
  - **Then** 该活动不再进入上新弹窗，用户可在“不感兴趣”列表恢复

- [ ] **AC-014：弹窗报名状态适配**
  - **Given** 上新弹窗包含用户已报名或已满的活动
  - **When** 用户查看该活动卡片
  - **Then** 已报名活动显示“查看报名”，已满活动显示“名额已满”且不能重复报名

- [ ] **AC-015：自动活动提醒**
  - **Given** 活动已设置开始时间，用户正式报名且已授权订阅消息
  - **When** 到达活动开始前三天或前一天
  - **Then** 用户收到对应微信订阅消息和站内通知，同一提醒节点不重复发送

- [ ] **AC-016：手动提醒**
  - **Given** 发起人或活动管理员选择全部正式参与人或指定参与人
  - **When** 点击发送固定活动提醒
  - **Then** 符合频率限制的正式参与人收到提醒，页面展示发送结果并保留发送记录

- [ ] **AC-017：飞书自动同步**
  - **Given** 活动已选择有效的飞书连接和目标多维表格
  - **When** 报名新增、修改、取消或活动被取消
  - **Then** 对应记录同步到目标多维表格，管理者可查看同步状态

- [ ] **AC-018：多人活动管理员协作**
  - **Given** 发起人为活动配置了多名活动管理员
  - **When** 任一活动管理员进入活动管理页
  - **Then** 可以编辑活动、审核报名、管理候补和群聊、取消参与资格、发送提醒及查看同步状态

### 5.2 边界与异常（Edge & Error Cases）

- [ ] **AC-019：长期活动不自动提醒**
  - **Given** 活动未设置活动时间
  - **When** 活动发布并持续开放
  - **Then** 活动按长期活动展示，不执行开始前三天和前一天提醒

- [ ] **AC-020：不足三天的提醒安排**
  - **Given** 活动发布或用户报名时距离活动开始不足三天
  - **When** 系统安排自动提醒
  - **Then** 只安排尚未错过的提醒节点，不补发已经错过的提醒

- [ ] **AC-021：无模板或未授权**
  - **Given** 未配置模板 ID 或用户未授权微信订阅消息
  - **When** 到达自动提醒时间
  - **Then** 不发送微信消息，但仍生成站内通知且不影响活动流程

- [ ] **AC-022：用户主动取消后重新报名**
  - **Given** 用户已正式报名且当前仍在报名截止前
  - **When** 用户确认取消报名
  - **Then** 释放正式名额、退出群聊，并允许用户在截止前重新报名

- [ ] **AC-023：管理员取消参与资格**
  - **Given** 发起人或活动管理员填写取消原因
  - **When** 确认取消某用户参与资格
  - **Then** 用户退出群聊并收到通知，且不能再次报名或进入该活动候补队列

- [ ] **AC-024：已通过资料修改待复审**
  - **Given** 用户报名已审核通过
  - **When** 在报名截止前修改报名资料
  - **Then** 正式名额和群聊身份保持不变，新资料显示为待复审

- [ ] **AC-025：资料复审被拒**
  - **Given** 已通过用户提交的新资料处于待复审
  - **When** 活动管理员拒绝新资料
  - **Then** 恢复上一次审核通过的资料，保留活动资格并通知用户重新修改

- [ ] **AC-026：报名后表单结构锁定**
  - **Given** 活动已经产生至少一条报名
  - **When** 管理员尝试删除字段、改变字段类型或改变选项含义
  - **Then** 操作被阻止并说明原因，但允许修改说明、排序和新增选填字段

- [ ] **AC-027：切换或退出圈子后保留报名**
  - **Given** 用户已报名某圈子活动
  - **When** 切换当前圈子或退出原圈子
  - **Then** 可从“我的活动”继续查看详情和群聊，但原活动不进入新圈子的列表和上新弹窗

- [ ] **AC-028：取消整个活动**
  - **Given** 活动发起人确认取消活动
  - **When** 取消操作完成
  - **Then** 停止新报名和候补转正，通知正式参与人及候补用户，群聊立即只读并同步活动取消状态

- [ ] **AC-029：无效活动不再上新**
  - **Given** 活动已取消、已下架或已结束
  - **When** 用户查看活动首页或冷启动上新弹窗
  - **Then** 该活动不作为可报名活动展示，也不能通过旧入口继续报名

- [ ] **AC-030：飞书同步失败不阻塞报名**
  - **Given** 飞书连接失效、目标无权限或同步暂时失败
  - **When** 用户提交有效报名
  - **Then** 小程序内报名正常完成，管理页显示失败原因并允许重试，重试不产生重复记录

- [ ] **AC-031：活动结束后群聊转只读**
  - **Given** 活动正常结束
  - **When** 结束时间未满 7 天或已经满 7 天
  - **Then** 未满 7 天时群聊可继续沟通，满 7 天后自动只读并保留历史消息

- [ ] **AC-032：没有可展示活动时不弹窗**
  - **Given** 用户可见活动均已失效或被标记为不感兴趣
  - **When** 小程序冷启动
  - **Then** 不展示空的活动上新弹窗

### 5.3 业务规则验证（Business Rules）

- [ ] **AC-033：报名人数分开统计** ← BR-004
  - **Given** 活动同时存在正式、待审核和候补用户
  - **When** 管理员或用户查看人数
  - **Then** 三类人数分别展示，只有正式报名成功用户计入正式报名人数

- [ ] **AC-034：发布范围隔离** ← BR-001, BR-002
  - **Given** 同时存在平台活动和圈子活动
  - **When** 不同圈子的用户查看活动列表
  - **Then** 所有人可见平台活动，圈子活动仅在其所属圈子范围展示

- [ ] **AC-035：发起人专属权限** ← BR-009
  - **Given** 活动管理员不是活动发起人
  - **When** 尝试转让发起人、取消整个活动、增删管理员或管理飞书连接
  - **Then** 操作入口不可用或操作被拒绝，只有发起人可以完成

- [ ] **AC-036：活动形式字段约束**
  - **Given** 管理员创建线下、线上或线上线下结合活动
  - **When** 缺少该形式要求的地点或参与方式并尝试发布
  - **Then** 发布被阻止并明确提示需要补充的字段

- [ ] **AC-037：地点和参与链接可见性**
  - **Given** 发起人将地点或参与链接设置为仅正式参与人可见
  - **When** 未报名、待审核、候补和正式参与用户分别查看详情
  - **Then** 只有正式参与用户可查看完整内容，其他用户看到受限提示

- [ ] **AC-038：手动提醒频率限制** ← BR-011
  - **Given** 某正式参与人在 24 小时内已收到该活动手动提醒
  - **When** 管理员再次选择该用户发送提醒
  - **Then** 系统阻止重复提醒并展示频率限制说明，候补用户始终不在“参加活动”提醒对象中

- [ ] **AC-039：报名资料权限与密钥脱敏**
  - **Given** 普通用户、活动管理员和活动发起人分别查看活动管理信息
  - **When** 访问报名资料或飞书连接信息
  - **Then** 普通用户只能查看本人资料，管理者按权限查看报名资料，任何页面均不展示完整连接密钥

- [ ] **AC-040：活动记录不可彻底删除** ← BR-012
  - **Given** 活动已经产生报名记录
  - **When** 管理者尝试删除活动
  - **Then** 只能取消或下架并保留历史记录，不提供彻底删除能力

## 6. 页面与入口清单

| 页面或入口 | 核心内容 |
|------------|----------|
| 底部“活动” | 活动首页、活动发现和状态筛选 |
| 广场“活动”分类 | 当前圈子活动与平台活动列表 |
| 活动上新弹窗 | 最多 5 个最新活动轮播及兴趣、详情、报名操作 |
| 活动详情 | 活动信息、可见地点或链接、报名状态、剩余名额、发起人和所属范围 |
| 活动报名页 | 自定义表单、报名提交和资料修改 |
| 我的活动 | 感兴趣、已报名、待审核、候补、已取消、已结束、不感兴趣 |
| 活动群聊 | 正式参与人沟通和活动管理 |
| 活动发布与编辑 | 基础信息、范围、时间、人数、报名表单、管理员和同步配置 |
| 报名管理 | 待审核、正式参与人、候补、已取消及资料复审 |
| 活动提醒 | 全部或指定正式参与人提醒及发送记录 |
| 飞书连接与同步 | 可复用连接、目标多维表格、同步状态和失败重试 |

## 7. 待后续技术设计处理的约束

- 当前项目虽然使用自定义底栏，但仍基于微信小程序官方 tabBar 配置，现有配置为 5 项；产品已确认需要 6 项固定底部入口，技术设计必须解决承载方式，同时保持现有视觉、动态显隐和角色切换体验。
- 活动介绍中的外部链接跳转受微信可打开域名及页面能力限制，技术设计需给出合法域名直接打开与其他链接复制提示的统一行为。
- 微信订阅消息依赖用户主动授权，不能把微信消息送达作为报名成功或提醒成功的唯一判定。
- 飞书连接涉及敏感凭证，技术设计必须满足安全存储、脱敏展示、权限隔离和可撤销要求。
