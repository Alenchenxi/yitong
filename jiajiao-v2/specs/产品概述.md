# 产品概述

> 状态:已确认(2026-10-17)
> 来源:jiajiao-v2 需求澄清阶段产物(基于 AmazingTalker 逆向分析 + 旧 jiajiao 源码评估,范围决策见会话记录)

## 1. 项目愿景 (Vision)

为单城市的 K12 家长与大学生/专职教师,提供一个「找老师→约课→付费→核销→评价」全流程线上闭环的本地家教服务平台:教师自主经营排班与定价,家长按真实排班约课,课时费核销后自动到账,平台以服务费率盈利。

## 2. 核心价值 (Value Proposition)

- **用户价值**:
  - 家长:资质透明、评价真实、价格明确的教师筛选;按周固定时段约课;资金由平台托管,未上课可退,纠纷有仲裁
  - 教师:免费入驻、自主定价排班;媒合派单带来生源;核销 24h 后课时费自动到微信零钱,无需申请提现
- **商业/技术价值**:平台侧以微信分账完成资金清结算(资金不落平台账户,规避二清),服务费率后台可配;领域模型参照 AmazingTalker 成熟产品结构(预约漏斗/排班规则/媒合票券/纠纷流程)设计,降低试错成本

## 3. 核心板块 (Core Modules)

### 3.1 学生端(发现与交易)
- **描述**:家长/学生的找老师与约课闭环
- **关键特性**:
  - 教师墙搜索(科目/年级/区域/价格/时段筛选;列表卡片不含排班)
  - 教师档案页(资质/经历/评价/定价/按周排班日历)
  - 预约下单:体验课(教师自定价)+ 按次课时包 + 每周固定周期订课;购物车聚合
  - 微信支付(付款即冻结待分账);我的课程/课时余量/订单
  - 评价(星级+教学风格标签)

### 3.2 教师端(供给经营)
- **描述**:教师的入驻、经营与履约
- **关键特性**:
  - 入驻:双轨制(大学生教员/专职教员,按身份交材料),材料必填项后台开关可调,人工审核
  - 排班:单次/周期规则,随时修改实时生效(推送失效通知,档案页快照权威,下单服务端原子校验);已约课时变更走协商改期/取消
  - 定价:体验课价 + 课时包价目;调价不影响已购课时
  - 派单承接位:媒合来的学生推荐 + 消息模板一键联系
  - 课时管理:今日课表、核销确认、结算明细(分账到账记录)

### 3.3 撮合与信任(平台服务)
- **描述**:连接供需双方并保障交易安全的平台能力
- **关键特性**:
  - 问卷媒合(学习票券):预算/目标/学段问卷 → 发体验券 → 系统媒合推荐
  - 站内 IM:WebSocket 实时 + 结构化消息模板 + 文件收发(无翻译)
  - 纠纷流程:24h 限时取消、未消课时可退、平台仲裁(仲裁期资金冻结不解冻);教师违约=自动全额退+信用记录
  - 通知中心:站内通知+红点,配微信订阅消息提醒;多角色底部导航(学生端/教师端)

### 3.4 运营后台
- **描述**:平台运营与治理(功能清单沿用旧 xhadmin,形态重做为前后端分离)
- **关键特性**:
  - 教师审核工作流(材料聚合预览/驳回原因/审核记录)
  - 纠纷仲裁台 + 资金审批流(退款/分账异常,双人复核)
  - 业务配置:抽成费率/入驻材料开关/分类年级科目/城市/体验券规则
  - 经营仪表盘:交易/媒合/供给漏斗统计

## 4. 目标用户 & 核心场景 (User & Scenes)

### 4.1 目标用户
- **家长(学生端)**:为 K12 孩子找本地学科辅导,看重资质背书、真实评价、价格透明与资金安全
- **教师(教师端)**:在校大学生教员(时间灵活、课表按学期变动)与专职教师(以此为业、需要稳定生源),诉求是低门槛入驻、生源稳定、结算即时
- **平台运营(后台)**:1-3 人小团队,审核教师、处理纠纷、配置规则、看数据

### 4.2 核心场景 (Key Use Cases)
- **场景 1**:家长在教师墙按「初二数学+本区+¥150-200/次」筛选 → 进档案页看资质与评价 → 选周六上午时段 → 购体验课 → 微信支付
- **场景 2**:体验课满意后,家长购 10 次课时包并订阅「每周六 9:00-11:00」周期订课
- **场景 3**:教师上课结束在教师端核销 → 24h 后课时费自动到微信零钱,平台服务费自动扣除
- **场景 4**:不确定怎么选的家长填媒合问卷(年级/科目/预算/期望时间)→ 领体验券 → 收到系统媒合的教师推荐 → 教师在派单承接位用消息模板主动联系
- **场景 5**:家长对第 3 次课不满,发起纠纷申请退剩余课时 → 平台在仲裁台审核 → 部分退款原路退回(该部分资金未分账,直接解冻退回)

## 5. 关键业务流程 (Core Workflows)

> **主交易链(资金链路,决定架构复杂度)**:
> 搜索/媒合 → 教师档案(按周拉排班) → 选时段加购(服务端原子校验时段有效性) → 购物车结算 → 微信支付**分账模式**(资金冻结待分账) → 线下上课 → 教师核销 → **24h 冷却期**(无纠纷/退款) → 自动分账:教师份额到零钱、平台服务费留存 → 学生评价;纠纷分支:仲裁期冻结 → 仲裁结论(原路退回/部分退+部分分账)

> **撮合获客链**:
> 家长填问卷 → 系统发体验券 + 生成学习票券(结构化需求单) → 匹配教师 → 推入教师端派单承接位 → 教师用消息模板经站内 IM 主动联系 → 转化进主交易链

## 6. 验收标准 (Acceptance Criteria)

- **功能完备性**:
  - 主交易链端到端跑通:注册登录 → 找老师 → 下单支付 → 核销 → 24h 后分账到账(沙箱/真实商户验证)→ 评价,无阻断性 Bug
  - 教师入驻审核、排班修改与实时同步、协商改期、纠纷仲裁退款、媒合问卷+派单+模板消息联系,全部可用
  - 多角色底部导航正确切换学生端/教师端视角;通知中心红点准确
- **技术指标**:
  - 下单时段校验无超卖(并发下不产生冲突预约)
  - 支付回调与分账指令幂等,对账可核(每笔订单资金状态可追溯)
  - 核心域(订单/排班/分账/仲裁)单元测试覆盖,关键流程有集成测试
  - 小程序冷启动与档案页打开体验流畅(分包加载,首屏 < 2s 量级)

## 7. 约束条件 (Constraints)

- 技术栈:uni-app 小程序 + NestJS 后端,新项目独立目录 `jiajiao-v2/`;旧 jiajiao 源码只读参考,可复制(登录逻辑、城市/年级/科目数据、打款封装思路)
- 微信生态约束:支付仅微信(分账 API,默认分账比例上限内);提醒依赖订阅消息(需用户授权,无主动推送)
- 合规:K12 定位按「家教信息服务」过小程序类目资质预核查,上架前完成;资金不落平台自有账户
- 团队:单人+AI 协作开发;运营人力 1-3 人,后台流程必须极简
- 单城市试点,首页/搜索/媒合限定同城

## 8. 项目边界 (Out of Scope)

- 短视频、教师团队裂变(面试票/培训票/导师体系)
- 在线课堂(仅数据模型预留课程形式字段,不接视频基建)
- 消息翻译、多币种/多区域
- 钱包充值/提现功能(仅留内部账务表;分账自动到账替代提现)
- 多城市、非微信端(App/H5 独立版)
