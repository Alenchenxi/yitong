# 酒店招聘页面改版 — 变更记录 CR-002

## 1. 变更概览

**变更标题**：分离推广归因与本人推广身份  
**变更类型**：修正  
**变更原因**：非推广员也会通过带 `inviter` 的推广链接进入，不能因此被识别为推广员。  
**发起日期**：2026-10-28  
**关联功能**：酒店招聘页面改版

## 2. 影响分析

| 影响范围 | 变更内容 |
|---------|---------|
| 页面状态 | 将报名归因码与本人推广码拆为两个独立变量 |
| 本地存储 | 保留 `inviter` 作为 30 天归因，新增 `promoter_self` 保存本人推广码 |
| 海报 | 二维码和海报邀请码改用本人推广码 |
| 报名 | 继续使用最初的 `inviter`，注册推广员不覆盖原归因 |

不修改后端接口、飞书字段、推广码格式和手机号去重规则。

## 3. 新增验收标准

- **AC-013：推广归因与本人身份分离**
  - **Given** 普通访客通过 `?inviter=p001` 进入页面
  - **When** 访客浏览岗位或提交报名
  - **Then** 页面保留申请入口，报名归因仍使用 `p001`；注册成为推广员后，海报使用新生成的本人推广码

## 4. 增量任务

### [x] Task-CR002-01：拆分前端推广状态

**做什么**：保留 `inviter` 归因状态，新增 `promoter_self` 本人推广状态，并分别用于报名和推广工具。

**涉及文件**：`public/index.html`

**验证标准**：
- 带 `inviter` 的普通访问不启用推广工具。
- 报名请求仍携带原 `inviter`。
- 注册成功后海报与链接使用本人推广码。

### [x] Task-CR002-02：回归验证

**做什么**：运行 UI 契约测试与真实 390px 浏览器状态验收。

**验证标准**：
- 普通访问、推广链接访问和本人推广员三种状态符合 AC-013。
- 既有筛选、报名表和移动端布局不受影响。
