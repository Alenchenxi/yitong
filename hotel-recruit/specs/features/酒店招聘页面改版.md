# 酒店招聘页面改版 — 功能需求说明书

## 1. 背景与价值

**为什么做**：现有 20 家酒店以区域折叠长列表展示，实拍图利用不足，待遇信息集中在长文本里，求职者难以快速比较岗位；普通访客还会看到推广工具，报名页也缺少费用、年龄和隐私说明。

**做成什么样**：求职者可以按地区快速筛选、用实拍图和结构化条件比较酒店，并在明确了解报名规则后完成报名；推广员仍保留原有归因与海报能力。

## 2. 范围

### 本次做

- 地区筛选与结果计数，默认展示全部 20 家酒店。
- 横向实拍首图、结构化待遇信息、差异亮点和酒店详情弹层。
- 普通访客的报名流程、常见问题和咨询方式。
- 报名免费、最低年龄、隐私用途说明与提交确认。
- 保留真实报名数、手机号更新、首次推广归因和推广海报。

### 本次不做

- 改造飞书字段或报名数据结构。
- 增加岗位搜索、薪资排序或多条件组合筛选。
- 编造或代填尚未提供的公开联系电话。

## 3. 用户与故事

| 编号 | 用户故事 | 关联 AC |
|------|---------|---------|
| US-001 | 作为求职者，我想快速筛选并比较酒店，以便选出适合自己的岗位 | AC-001 至 AC-004 |
| US-002 | 作为求职者，我想在报名之前看清费用、年龄和信息用途，以便放心提交 | AC-005 至 AC-008 |
| US-003 | 作为推广员，我想继续使用专属链接和海报，以便维持推广归因 | AC-009, AC-010 |

## 4. 核心流程与业务规则

1. 访客进入页面，看到真实数据汇总和全部酒店岗位。
2. 访客按地区筛选，查看卡片亮点与酒店详情。
3. 访客选择酒店，阅读报名说明并填写表单。
4. 系统校验信息后提交；相同手机号再次提交时更新酒店，不改变首次推广归属。

- BR-001：首屏薪资、春节工资和报名人数只能来自真实数据。
- BR-002：普通访客可以看到“申请成为推广员”入口，但不显示推广业绩和推广海报工具；通过他人的推广链接进入只建立报名归因，不获得推广员身份。
- BR-003：最低报名年龄为 16 周岁，部分岗位可能要求 18 周岁，以酒店审核为准。
- BR-004：联系电话未配置时不得显示虚假号码。

## 5. 验收标准

### 5.1 正常流程

- [ ] **AC-001：默认展示全部岗位**
  - **Given** 配置中存在 20 家酒店
  - **When** 访客打开页面
  - **Then** 地区筛选默认选中“全部”，页面显示 20 个岗位结果

- [ ] **AC-002：地区筛选**
  - **Given** 访客位于岗位列表
  - **When** 访客选择瑞安、鹿城、瓯海或其他
  - **Then** 页面只显示对应区域酒店，并同步显示准确数量

- [ ] **AC-003：结构化比较**
  - **Given** 任一酒店卡片可见
  - **When** 访客浏览卡片
  - **Then** 能直接看到日薪、工时、月休、春节工资和该酒店差异亮点

- [ ] **AC-004：查看酒店详情**
  - **Given** 酒店存在实拍照片和待遇信息
  - **When** 访客点击“查看详情”
  - **Then** 弹层展示最多 3 张实拍图，以及住宿、加班、车费、提成和地址等完整信息

- [ ] **AC-005：可信报名说明**
  - **Given** 普通访客浏览页面或报名表
  - **When** 查看报名说明
  - **Then** 页面明确显示不收取报名费、联系流程、最低年龄和信息用途

- [ ] **AC-006：报名提交**
  - **Given** 访客年满最低年龄且填写完整有效信息并确认报名说明
  - **When** 点击“确认并提交报名”
  - **Then** 页面提交现有报名接口并展示成功或更新结果

### 5.2 边界与异常

- [ ] **AC-007：未达到最低年龄**
  - **Given** 出生年月对应年龄不足 16 周岁
  - **When** 访客提交报名
  - **Then** 页面阻止提交并明确提示最低年龄要求

- [ ] **AC-008：配置或网络异常**
  - **Given** 岗位接口加载失败或真实报名数接口失败
  - **When** 页面加载
  - **Then** 岗位区提示刷新重试；报名数失败时不显示虚假数字

### 5.3 业务规则验证

- [ ] **AC-009：普通访客不显示推广工具** ← BR-002
  - **Given** 访客没有本机推广员身份，包括通过他人的推广链接进入
  - **When** 打开页面
  - **Then** 页面显示“申请成为推广员”入口，但不显示业绩查询或推广海报按钮

- [ ] **AC-010：推广身份保留能力** ← BR-002
  - **Given** 访客已在本机完成推广员注册并保存自己的推广码
  - **When** 浏览页面
  - **Then** 页面显示推广工具、业绩入口和海报生成功能

- [ ] **AC-011：联系电话降级** ← BR-004
  - **Given** 配置中没有公开联系电话
  - **When** 页面渲染咨询区
  - **Then** 显示“报名后专员回电”，不渲染拨号链接或虚假号码

- [ ] **AC-012：推广员申请入口转换** ← BR-002
  - **Given** 普通访客打开页面
  - **When** 完成推广员注册并获得推广码
  - **Then** 申请入口隐藏，页面显示高对比度的“生成推广海报”按钮和业绩入口

- [ ] **AC-013：推广归因与本人身份分离** ← BR-002
  - **Given** 普通访客通过 `?inviter=p001` 进入页面
  - **When** 访客浏览岗位或提交报名
  - **Then** 页面保留“申请成为推广员”入口，报名归因仍使用 `p001`；若访客注册成为推广员，其海报使用新生成的本人推广码

- [ ] **AC-014：注册成功后的海报引导**
  - **Given** 访客已在当前页面完成推广员注册
  - **When** 查看注册成功弹窗
  - **Then** 弹窗明确提示无需重新打开专属链接，关闭弹窗后可直接在当前页面生成并保存本人专属海报

## 变更日志 (Change Log)

### CR-001: 恢复推广员申请入口并增强海报按钮对比度 (2026-10-28)

**变更类型**: 微调

**变更原因**: 普通访客需要明确入口申请成为推广员，推广员需要更醒目的海报生成按钮。

**变更内容**:
- 普通访客恢复“申请成为推广员”入口，但推广工具继续按身份控制。
- 注册成功后自动隐藏申请入口并显示推广工具。
- “生成推广海报”按钮改用亮色文字与高对比背景。

### CR-002: 分离推广归因与本人推广身份 (2026-10-28)

**变更类型**: 修正

**变更原因**: 非推广员通常通过他人的推广链接进入，地址栏中的 `inviter` 不能作为本人推广员身份。

**变更内容**:
- `inviter` 仅用于访问与报名归因。
- 新增本机 `promoter_self` 状态保存本人推广码。
- 通过推广链接进入的普通访客继续显示申请入口，不显示他人的推广工具。
- 注册成功后使用本人推广码生成链接和海报，不覆盖原报名归因。

### CR-003: 更新注册成功后的海报引导 (2026-10-28)

**变更类型**: 微调

**变更原因**: 注册完成后当前页面已具备本人推广码和海报能力，无需引导用户重新打开专属链接。

**变更内容**:
- 成功弹窗改为提示关闭弹窗后直接点击当前页面右下角生成专属海报。
- 删除“重新打开你的链接”这一过期操作步骤。
