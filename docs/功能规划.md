# 燚桐小程序功能规划

> 本文是后续产品拆分、开发排期和验收的功能基线。后续实现以本文为准；除非用户明确调整，否则不要再按旧 MVP 范围补功能。

## 0. 范围原则

- 用户端分为三大核心模块：表白墙、树洞、兼职。
- 用户端底部 tabBar 含「广场」tab（左一位置）—— **圈子（Community）首页**：用户可加入/创建/切换圈子，圈子内承载表白墙/树洞/兼职三类内容（三类都按圈子隔离）。广场页含圈子头卡（LOGO+名称+动态数+成员数）、广告位轮播（Banner）、今日上头（近24h 浏览量 Top10）、4 tab（圈子动态/表白墙/树洞/兼职）；详见 §1.8。
- 表白墙按完整校园表白墙体验建设，不停留在发帖/点赞/评论 MVP。
- 树洞保留匿名身份、灵魂测试、匹配、1v1 聊天、群聊广场，不做礼物、打赏、虚拟币、付费装扮、直播打赏、短视频、视频聊天、实时语音通话、语音房、多人连麦、K 歌房。
- 树洞语音只做异步语音消息：录音、上传、播放、时长展示、保存聊天记录；不做语音消息举报。
- 兼职按青团社式找兼职、报名、简历、沟通、评价保障、商家招聘闭环建设。
- AI 相关能力全部不做，包括 AI 推荐、AI 破冰、AI 回复建议、AI 陪伴、AI 标签生成、AI 安全识别等。

## 1. 表白墙模块

### 1.1 内容流

目标：让用户打开表白墙后有可持续浏览的校园内容流，而不是只有单一列表。

功能清单：
- 推荐流
- 最新流
- 热门流
- 关注流
- 置顶最热帖子
- 滚动加载前十条
- 今日上头
- 今日上头对应滚动列表

落地说明：
- 推荐流初期可先用规则排序：置顶、加精、热度、时间衰减。
- 热门流按点赞、评论、收藏、分享、发布时间计算热度分。
- 关注流只展示已关注作者的内容。
- 今日上头作为运营位，展示当天热度最高或后台配置的内容集合。

### 1.2 发布能力

目标：支持用户完成正式表白、匿名表达、草稿沉淀和后续管理。

功能清单：
- 图文表白
- 匿名/实名发布
- 选择标签
- 图片发布
- 视频发布
- 表情发布
- 草稿箱
- 定时发布
- 发布后编辑
- 发布后删除
- 私密投稿
- 仅自己可见草稿

落地说明：
- 发布前必须走内容安全审核和关键词屏蔽。
- 匿名发布的展示身份与真实 uid 隔离；后台可按合规需要追溯。
- 草稿仅用户本人可见，不进入公开审核队列。
- 定时发布到点后进入审核或发布流程，不能绕过审核。

### 1.3 互动能力

目标：补齐社区互动闭环，让帖子有关系链、讨论和治理能力。

功能清单：
- 点赞
- 收藏
- 评论
- 评论回复
- 二级评论
- 评论点赞
- 分享到微信
- 举报
- 拉黑用户
- 关注作者
- 进入作者主页
- @用户
- 热评置顶

落地说明：
- 评论、回复、@ 提醒都要进入表白墙来源的消息通知。
- 拉黑后互相不可见或不可互动，具体规则开发前单独确认。
- 热评置顶可先由热度自动选取，后台再补人工置顶。

### 1.4 搜索与发现

目标：让用户能找帖子、找人、找话题。

功能清单：
- 搜索帖子内容
- 搜索用户昵称
- 搜索话题
- 历史搜索
- 热门搜索

落地说明：
- 搜索记录存用户维度，支持清空。
- 热门搜索可先按搜索次数统计，后续补后台运营配置。

### 1.5 我的表白墙

目标：入口放在“我的”页面下，进入后用 tab 列表承载个人相关内容。

功能清单：
- 我的发布
- 我的匿名发布管理
- 我的点赞
- 我的收藏
- 我的评论
- 关注/粉丝

落地说明：
- 匿名发布管理只能本人查看，不在公开主页展示真实身份。
- 我的评论要能跳回原帖和对应评论位置。

### 1.6 表白墙消息通知

目标：所有通知必须注明来源是“表白墙”，避免和树洞、兼职混淆。

功能清单：
- 点赞通知
- 评论通知
- 回复通知
- 关注通知
- 内容被下架通知
- 微信订阅消息关键提醒

落地说明：
- 站内消息保留完整记录。
- 微信订阅消息只做关键提醒，且必须由用户主动授权。

### 1.7 安全与运营

目标：保证社区内容可控、可审核、可运营。

功能清单：
- 内容安全审核
- 关键词屏蔽
- 举报处理
- 用户禁言/封禁
- 帖子置顶
- 帖子加精
- 帖子下架
- 活动专题
- 校园话题运营

落地说明：
- 发帖、评论、回复、图片、视频都必须纳入审核或风控。
- 后台需支持举报处理、封禁、禁言、下架、置顶、加精。

### 1.8 广场（圈子 Community 首页）

定位：用户端首屏的**圈子（Community）首页**。圈子是用户可加入/创建/切换的社区（区别于表白墙发帖分类 `Circle`，存量 5 分类保留为发帖分类不算圈子），圈子内承载表白墙/树洞/兼职三类内容（三类都按圈子隔离）。与表白墙/树洞/兼职各自独立入口并存：广场侧重「圈子内跨模块一次浏览」；表白墙侧重完整社区体验（含运营位/关注/4 tab）；树洞首页侧重匿名身份+情绪+匹配+群聊广场入口；兼职首页侧重岗位发现。

页面要点（按目标 UI）：
- 顶部搜索栏**左侧圈子切换按钮**（当前圈 LOGO/首字占位，点开圈子切换页）+ 搜索栏（进入**内容搜索**：表白墙/树洞/兼职 3 tab）+ 公告栏
- **圈子头卡**：LOGO + 名称（动态）+ 动态数 + 成员数；点击进圈子列表/切换页
- **广告位轮播**：Banner（管理端可配，圈子 + 全局占位）
- **今日上头**：近24h **浏览量** Top10（表白墙帖 + 树洞帖），横向滚动展示
- **4 tab**：圈子动态（表白墙+树洞+兼职混合流）/ 表白墙 / 树洞 / 兼职
  - 圈子动态 = 三源混合流，**曝光度 = 付费推广（boostUntil）前置**，其余按时间
  - 表白墙 / 树洞 tab = 圈子作用域列表，付费推广前置（不引入浏览/点赞加权综合分）
  - 兼职 tab = 圈子作用域岗位列表（默认排序）
- 匿名帖卡片降级：去真实头像/昵称，显示「匿名」标识 + 匿名昵称 + mood；anonToken 缺失时点赞/评论 disabled + toast
- 悬浮发帖按钮（发帖归属当前圈子）

圈子交互页面（对照目标 UI）：
- **加入圈子页**：未加入圈子用户进入广场 → 先展示加入页；点圈子卡片即加入并置为当前，`switchTab` 回广场；页内「创建圈子」入口
- **创建圈子页**：LOGO + 名称 + **类型**（校园/兴趣/生活/兼职，必选）+ **所在地区** + **所在地点** + 简介；提交后加入并成为当前圈
- **圈子切换页**（广场搜索栏左侧切换按钮点开）：当前圈子头卡 + 右上角「···」→ 底部菜单「退出圈子」；下方「我的圈子」列表 + 圈子广场 / 搜索圈子 / 创建圈子入口
- **圈子广场页**：左侧类型列表（全部 + 校园/兴趣/生活/兼职）+ 右侧该类型圈子列表；点圈子 → 切换并回广场；非成员圈子卡片内「加入」按钮
- **圈子搜索页**：历史搜索 + 结果列表；点结果 → 切换并回广场
- **内容搜索页**（广场搜索栏落地）：3 tab 表白墙 / 树洞 / 兼职，均按当前圈子作用域搜索

落地说明：
- **圈子（Community）**：新数据模型 `Community` / `CommunityMember` + `User.activeCommunityId`；字段含 `category`（类型：校园/兴趣/生活/兼职）、`region`（所在地区）、`location`（所在地点，后两者纯展示字符串）；接口 `/community/list?category=|mine|active|:id|POST|:id/join|:id/leave|switch|search?keyword=`；建圈 3/min + 内容审核；**已去掉默认圈子惰性自动加入**：未加入圈子 → `GET /community/active` 返回 null → 广场 onShow 引导加入页；写路径抛 `80014 请先加入圈子`（表白墙发帖为严格门；树洞发帖有匿名档案时生效、无档案静默回退默认圈；发岗未显式选圈时生效、商家显式选圈仅校验 ACTIVE）；读路径（feed/banners/今日上头）缺省兜底 `DEFAULT_COMMUNITY_ID`（cm_default），未加入也可浏览默认圈。
- **三类内容圈属**：Post / AnonymousPost / JobPost 均加 `communityId`；发帖/发树洞帖/发岗位写入当前圈子（发岗可显式选圈）；feed 按 `communityId` 过滤。
- **数据源**：圈子动态 `/square/feed?communityId=&sort=recommend|latest`（union PostVo + AnonymousPostVo + JobPostVo，boost 前置）；表白墙 tab 复用 `/posts/feed?communityId=`；树洞 tab 复用 `/treehole/posts?communityId=`；兼职 tab 复用 `/job-posts?communityId=`；今日上头 `/square/today-hit`；广告位 `/square/banners`。
- **内容搜索数据源**：表白墙 `/posts/search?q=&communityId=`；树洞 `/treehole/posts?keyword=&communityId=`；兼职 `/job-posts?keyword=&communityId=`（历史搜索沿用表白墙搜索记录能力）。
- **浏览量**：ContentView（target+viewer+hourBucket 去重）记录到详情浏览；今日上头 = 近24h 行数聚合 Top10。
- **匿名卡片点击**：跳树洞详情页 `/pages/treehole/detail/index?id=...`；点赞走 anonToken 路径（`toggleAnonPostLike`），独立于表白墙 uid 点赞。
- **anonToken 缺失体验**：匿名帖仍展示，点赞/评论 disabled + toast「请前往树洞签发匿名身份后互动」；表白墙帖不受影响。
- **树洞/兼职独立入口保留**：树洞首页 + 群聊广场 + 匹配入口不变；兼职首页岗位发现不变（全局视图）；广场内按圈子过滤。
- **启动路由不变**：user 角色启动默认落广场；表白墙/树洞/兼职 tab 保持完整入口。
- **树洞匿名红线必须守住**：union 后 FeedItemVo 严禁回填真实 uid/昵称/头像；AnonBlock 屏蔽关系延续到广场 union 列表；`content_views` 中 anon_post 的 viewerKey 用 anonId 绝不存真实 uid。
- **圈子创建审核（CR-004）**：管理端「全局设置」tab 一键开关 `community.need_review`（默认 false，开箱即用延续旧 ACTIVE 行为）。开启后：
  - 用户创圈进 `status=PENDING` 队列，**不切** `user.activeCommunityId`（避免 `getActiveCommunityId` 抛 80014）
  - 读路径（`/community/list` / `search` / `recommend` / `cm_default` 兜底）只返回 `status=ACTIVE` 圈 —— PENDING 圈对其他用户/搜索/推荐不可见
  - creator 视角经独立接口 `GET /community/mine/all` 按 status 分桶（已加入 / 待审核 / 未通过）查看
  - admin ops「圈子」sub-tab 多 tab 化（全部 / 待审核 / 已通过 / 已禁用）+ 通过/拒绝按钮，拒绝 reason 必填 1-200 字写进 `Community.rejectReason`
  - 通过 / 拒绝均发 Notification（type=community_approved/rejected，归 system 类）通知 creator + 微信订阅消息 fire-and-forget；每次审核留痕 `ModerationRecord(targetType='community')`
  - 被拒圈 creator 可在「我的圈子-未通过」tab 点「重新提交」（`POST /community/:id/resubmit`），重跑内容审核后回到 PENDING，支持多轮被拒→重提→再被拒
  - 0 存量数据迁移：旧 ACTIVE 圈不受开关切换影响

## 2. 树洞模块

### 2.1 匿名身份体系

目标：建立树洞专用匿名身份，不暴露真实 uid。

功能清单：
- 匿名身份生成
- 匿名昵称
- 虚拟头像/Avatar
- 头像装扮
- 个性标签
- 兴趣标签
- 心情状态
- 匿名身份保护，不暴露真实 uid
- 黑名单/屏蔽

落地说明：
- anonToken、anonId、树洞内容表不得直接包含真实 uid。
- 头像装扮只做免费配置，不做付费装扮。
- 黑名单/屏蔽影响广场、匹配和聊天可见性。

### 2.2 灵魂测试与画像

目标：用问卷和标签支撑匹配，不接 AI。

功能清单：
- 性格测试
- 兴趣测试
- 三观问卷
- 心情问卷
- 标签画像
- 匹配度计算
- 相似灵魂推荐
- 每日匹配报告

落地说明：
- 匹配度用规则模型实现，例如标签重合、问卷答案相似度、心情状态匹配。
- 每日匹配报告基于规则统计生成，不接 AI 生成内容。

### 2.3 树洞广场

目标：提供匿名图文内容流和情绪分类浏览。

功能清单：
- 推荐广场
- 最新广场
- 情绪分类：开心、emo、吐槽、求安慰、学习、恋爱、迷茫
- 话题广场
- 图文瞬间
- 匿名评论
- 点赞
- 收藏
- 分享
- 举报
- 屏蔽

落地说明：
- 不做短视频瞬间。
- 推荐广场初期用规则排序，不做 AI 推荐。
- 匿名评论同样不得暴露真实 uid。

### 2.4 匹配玩法

目标：支持匹配后解锁聊天，形成树洞核心社交链路。

功能清单：
- 灵魂匹配
- 随机匹配
- 兴趣匹配
- 心情匹配
- 限时聊天
- 匹配后解锁聊天
- 匹配历史
- 重新匹配
- 不喜欢/跳过
- 匹配安全提示

落地说明：
- 不做实时语音匹配。
- 匹配算法初期用规则，不接 AI。
- 未匹配的匿名双方不能绕过接口直接聊天。

### 2.5 1v1 聊天

目标：匹配后支持文字、图片、语音消息聊天。

功能清单：
- 文字消息
- 图片消息
- 语音消息
- 表情
- 撤回
- 已读/未读
- 拉黑
- 举报
- 聊天记录
- 断线重连
- 在线状态
- 破冰问题
- 聊天安全审核

语音消息范围：
- 录音发送
- 语音上传
- 语音播放
- 语音时长展示
- 语音消息保存到聊天记录

明确不做：
- 语音消息举报
- 实时语音通话
- 视频聊天
- AI 回复建议

### 2.6 群聊广场与群聊

目标：支持用户发现、创建、加入文字群聊。

功能清单：

- 推荐群聊

- 群聊分类：学习、情绪陪伴、游戏、恋爱、吐槽、同校

- 加入群聊

- 文字群聊消息

## 3. 兼职模块

### 3.1 找兼职首页

目标：提供接近青团社的岗位发现入口。

功能清单：
- 推荐岗位
- 附近岗位
- 最新岗位
- 热门岗位
- 精品兼职
- 急招岗位

落地说明：
- 附近岗位需要岗位地点结构化，初期可先按工作地点文本筛选，后续再接地图坐标。
- 推荐岗位初期按规则，不接 AI。

### 3.2 岗位分类

功能清单：
- 餐饮
- 零售
- 促销
- 展会
- 家教
- 校园代理
- 线上兼职
- 问卷/调研
- 实习
- 长期兼职
- 日结
- 周结
- 月结

落地说明：
- 分类需要成为岗位结构化字段，不只做前端静态筛选。

### 3.3 筛选搜索

功能清单：
- 关键词搜索
- 工作地点
- 薪资范围
- 结算方式

## 5. 验收原则

- 每个功能必须有用户入口、后端数据模型/API、权限校验、异常处理和消息/审核策略。
- 匿名相关功能必须证明不泄露真实 uid。
- 支付金额必须服务端计算。
- 内容发布、评论、聊天、举报相关功能必须考虑内容安全和后台处理。
- 微信订阅消息只能作为关键提醒，不替代站内消息。
- 不做项不得以“占位功能”形式偷偷接入。
