# BUG 修复报告

## 基本信息

**日期**：2026-08-10
**模块/功能**：用户端小程序 — 商家入驻（`pages/merchant/register`）→ 商家端 shell（`pages/merchant/index`）跳转
**严重级别**：高 — 阻断核心流程。新商家提交入驻后无法进入商家端，页面无任何出口（只能靠系统返回手势/杀进程），且线上 prod 路径 100% 必现，无绕过方案。

## 问题

**期望行为**：商家在入驻页填完店铺名称 / 营业执照号 / 联系电话并提交成功后，直接进入商家端页面（未过审时进商家端「我的」，由认证状态卡展示「资质审核中」）。

**实际行为**：提交后 toast 显示成功，但页面原地不动，停留在入驻页，进不了商家端。

**复现方式**：
1. 用户端小程序 → 角色选择页选「商家」登录（新用户，未入驻）
2. `pages/merchant/index` onLoad 入驻探测 `GET /merchant/profile` 返回 60002 → `wx.redirectTo` 到入驻页（**页面栈此时只剩入驻页一页**）
3. 填写三个字段 → 点提交 → 接口返回成功
4. 观察：线上（`NODE_ENV=production`，商家状态 `PENDING`）稳定卡在入驻页；本地 dev 在 `switchRole` 抛错时同样卡住

**环境**：微信开发者工具 / 体验版；后端 NestJS `apps/server`，本地 dev（`MODE=dev`，register 自动过审返回 APPROVED）与线上 prod（`NODE_ENV=production`，register 返回 PENDING）两套路径均受影响。

## 根因

入驻页的两条提交成功出口都不可靠，且入驻页本身通常是页面栈的**栈底**：

1. **主因（prod 必现）**：入驻页几乎总是由商家 shell 探测「未入驻」后经 `wx.redirectTo` 进入的，`redirectTo` 会替换栈顶，页面栈里只剩入驻页自己。而待审核分支写的是 `setTimeout(() => wx.navigateBack(), 800)` —— 没有上一页，`navigateBack` 直接失败，没有任何兜底，用户被钉死在入驻页。线上 register 返回 `PENDING`，走的正是这条分支。

2. **次因（dev 偶现）**：过审直通分支写的是 `await app.switchRole('merchant')` 后再 `reLaunch`。`switchRole` 一旦抛错（2026-08-10 提交 5ac6798 把 `switchRole` 收紧为「必须已拥有角色且 merchants.status='APPROVED'」后更易触发，PENDING 会返回 403/60002；网络异常亦然），异常被 `submit()` 外层的 `catch {}` 静默吞掉，后续 `reLaunch` 不再执行 —— 同样原地卡死。

3. **连带发现**：商家「我的」认证状态卡里，REJECTED 的提示、驳回原因、「重新提交资质」按钮串在同一条 `wx:elif` 链上。`wx:if/wx:elif` 是互斥语义，第一条 REJECTED 命中后另两条永不渲染，导致 8ad0cf1 上线的「驳回后重新提交」入口在 UI 上根本点不到 —— 被驳回的商家同样没有出口。

4. **连带发现**：入驻页 onLoad 对「REJECTED 且不带 `?mode=resubmit`」的用户只回填表单就 `return`，页面停在 register 模式；此时提交会调 `POST /merchant/register` 被后端 60001「已入驻，不能重复申请」拒掉，页内又无出口按钮 —— 又一个死胡同。

## 修复

**改了什么**：

| 文件 | 改动 | 原因 |
|------|------|------|
| `apps/user-miniprogram/pages/merchant/register/index.ts` | 新增模块级 `backOrShell(tab)`：`getCurrentPages().length > 1` 才 `navigateBack`，否则 `reLaunch` 回商家 shell | 消灭「栈底 navigateBack 失败 → 卡死」这一类隐患，页内所有返回统一走它 |
| 同上 | submit 的 PENDING 分支由 `navigateBack` 改为 `wx.reLaunch('/pages/merchant/index?tab=profile')` | 提交成功后确定性进入商家端「我的」，由认证状态卡展示「资质审核中」 |
| 同上 | APPROVED 分支 `app.switchRole('merchant')` 加 `.catch(() => {})` | 切角色失败不再阻断跳转；已验证商家接口只校验 `merchants` 行存在、不校验 JWT role，原 token 照样能用 shell |
| 同上 | toast 文案按状态区分（APPROVED「入驻成功」/ PENDING「已提交，等待审核」） | 原来无论是否过审都提示「入驻成功」，与实际状态不符 |
| 同上 | onLoad 的 REJECTED 分支强制切 resubmit 模式（setData mode/title + `setNavigationBarTitle`） | 让不带 mode 进来的 REJECTED 用户走 reapply 通路（而非被 60001 拒），并有确定性出口 |
| 同上 | onLoad「非 REJECTED 误入 resubmit」分支的 `navigateBack` 换成 `backOrShell()` | 同一类栈底隐患 |
| `apps/user-miniprogram/components/merchant-panels/profile/index.wxml` | REJECTED 的 tip / 驳回原因 / 「重新提交资质」按钮由 `wx:elif` 链改为 `<block wx:elif>` 内同层渲染 | `wx:elif` 互斥导致后两者永不渲染，重新提交入口点不到 |

**影响范围**：仅用户端小程序前端导航与渲染，未改任何后端逻辑，未触碰 2026-08-10 `switchRole` 的安全收紧（REJECTED / 已撤销角色仍拒绝切换）。受影响面：商家入驻提交、驳回后重新提交、商家「我的」认证状态卡三处。

## 遗留问题

- **微信开发者工具人工验收未做**（前端交互无法自动化）：需跑一遍「新用户选商家 → 入驻表单 → 提交 → 应落在商家『我的』页并显示资质审核中」，以及「admin 驳回后 → 商家『我的』能看到并点到『重新提交资质』」。
- 商家相关现成 smoke 因真实微信凭证已配置、wx-login mock 关闭而无法直接跑；后续可给测试脚本统一加「自签 JWT」登录 helper，恢复回归能力。
- PENDING 商家进 shell 后 token 角色可能仍是 USER（从用户端「我的」进入的场景），冷启动 `routeToRoleHome` 会回用户端。符合「未过审不算商家」语义，但体验上略不连贯；可考虑放宽 `switchRole` 允许 PENDING（该安全收紧真正要拦的是 REJECTED 和被撤销角色）。
- 商家 shell 在 PENDING 状态下未对「发布岗位」入口做灰态，用户点了才会被后端 60003 拦下弹 toast。
- 「PENDING 状态下商家接口必须可用」目前是隐式约定（除 `checkApplyReminder` 外均只校验 merchants 行存在）。若将来有人给某个商家接口加 `status === APPROVED` 守卫，PENDING shell 会立刻崩；建议在 `merchant.service` 补注释固化该约定。
