# 燚桐商家端开发计划

> 本文记录商家端对标页面后的可落地功能范围。后续商家端开发以本文为专项计划，同时遵守 `docs/功能规划.md`、`docs/任务规划.md` 和 `docs/UI设计规范.md`。

## 0. 范围原则

- 商家端是燚桐平台的一部分，不做成独立品牌；视觉继续使用统一主色 `#F9C801`。
- 商家端保留五个主入口：候选人、职位、发布、消息、我的。
- 涉及微信能力的配置统一放 `.env.example`，本地真实值由用户补到 `apps/server/.env`，代码不得直接写死密钥或模板 ID。
- 微信订阅消息做，用于报名、录用、未录用、完成、支付等关键提醒。
- 微信支付做，支付金额必须由服务端按 `PricingConfig` 计算，不信前端金额。
- 第三方服务不做；已有微信支付、微信订阅消息除外。

## 1. 明确不做项

以下能力不排期、不占位、不做 UI 暗示：

- 附近求职者
- 招聘道具
- 我的权益
- 企业认证福利
- 我要求职
- 更多服务
- 邮件通知
- 第三方在线客服
- 第三方实名认证
- 第三方虚拟号
- 第三方开票

## 2. 当前实现基线

当前已有基础：

- 商家入驻：店铺名称、营业执照号、联系电话、平台审核。
- 商家资料：资料查看、店铺名称和联系电话编辑。
- 职位：商家岗位列表、岗位发布、付费发布入口、岗位详情。
- 报名：按岗位查看报名、查看简历快照、查看报名问题回答、录用、拒绝、批量录用/拒绝、标记完成。
- 评价：学生评价商家、商家评价学生。
- 数据：浏览量、报名量、状态分布、转化率。
- 消息：站内通知列表、未读数、全部已读、按目标跳转。
- 订单：商家订单列表、退款入口。
- 支持：后端已有薪资保障规则、工单创建和工单列表接口。

当前主要缺口：

- 候选人页还是说明页，没有真实候选人聚合列表。
- 职位页缺搜索、状态筛选、今日数据和主动下架/编辑岗位。
- 消息页是通用消息列表，缺商家消息分类和订阅提醒引导。
- 我的页还是商家资料页，缺商家工作台式菜单、帮助中心、反馈、设置入口。
- 帮助中心前端未实现；报名处理规则和常见问题需要做静态 FAQ。
- 支付生产参数和微信订阅模板参数需要统一在 `.env.example` 表达清楚。

## 4. 静态 FAQ 初稿

### 报名处理规则

- 用户报名后，报名状态为“待处理”，商家应先查看简历和报名问题回答。
- 信息不足时，商家可以先通过站内消息或用户授权联系方式联系候选人。
- 候选人合适时，商家可录用；不合适时，商家应标记未录用。
- 候选人已沟通但暂不决定时，可先标记“已联系”或“合适/不合适”。
- 商家录用后，完成兼职可标记“已完成”，用户和商家可进行评价。
- 用户取消报名后，商家不可再录用该报名记录。

### 常见问题

- 岗位审核多久完成：平台审核通过后岗位才能公开展示；开发环境可自动通过，生产环境按后台审核结果为准。
- 为什么无法发布岗位：需要先完成商家入驻并通过平台资质审核。
- 为什么创建岗位后还是待发布：岗位创建后需要完成付费发布，支付成功后才公开展示。
- 如何修改岗位内容：后续在职位管理中提供编辑入口，编辑后按审核/发布规则处理。
- 如何下架岗位：后续在职位管理中提供主动下架入口；平台也可因违规下架岗位。
- 如何处理退款：订单页可申请退款，生产环境走微信退款接口，退款后岗位将同步处理。
- 如何开启报名提醒：商家可在消息页或职位页授权微信订阅消息；未授权时仍可收到站内消息。
- 如何投诉用户：在报名详情中发起投诉，平台后台处理。
