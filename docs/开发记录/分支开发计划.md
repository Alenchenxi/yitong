## 0.1 ⚠️ 2026-07-09 需求变更（本版核心调整）

1. **IM 方案替换**：腾讯云 IM (TIM) → **MobileIMSDK**（开源，Apache-2.0，Node 服务端 + 微信小程序端原生 SDK，WebSocket 传输，自带 QoS/心跳/重连/离线存储）。业务层（会话/匹配/消息历史）仍由 NestJS 自管，MobileIMSDK 只管实时传输。
2. **三端合一**：取消独立「商家端小程序」`apps/merchant-miniprogram` 与「管理端 web」`apps/admin-web`。**全部合进 `apps/user-miniprogram` 一个小程序**，进入先选角色（用户/商家/管理员）→ 微信登录 → 进对应功能。
3. **登录流程改造**：进入小程序 → 角色选择页 → `wx.login` → `POST /auth/wx-login { role }` → token → 进首页。
4. **管理员授权**：预设绑定 openid--只有预先在 `AdminUser.openid` 绑定的微信号，选「管理员」角色登录才放行（发 admin token）；否则拒绝（`10003`）。普通用户选管理员不放行。
5. **多角色**：一个微信账号可同时拥有多个角色（用户/商家/管理员），存 `UserRole` 关联表（userId + role 唯一）。去掉 `User.role` 单值字段，当前角色由 `token.role` 携带。角色获得：用户角色默认有；商家角色由 Merchant APPROVED 时加；管理员由 AdminUser.openid 绑定时加。
6. **角色切换**：静默切换--前端「切换角色」入口 -> 静默 `wx.login` -> `wx-login(newRole)` -> 新 token -> 切界面，**不退出微信**。后端校验 `UserRole` 拥有目标角色（管理员额外校验 `AdminUser.openid`）。开发时多角色切换方便。

> 影响的飞书文档：《开发路线图》(overwrite)、《技术栈》《API设计规范》《数据模型设计》《小程序功能模块设计方案》(各 append 变更声明)。原文档涉及腾讯云 IM / TIM / 独立商家端 / admin-web 的内容，以本计划 + 路线图为准。

## 2. 各分支详细 brief

> 每条 brief 含：范围 / 涉及文件 / API（飞书章节）/ 数据模型 / 依赖 / 暴露契约 / 完成标准 / 主要隐患。

### 2.1 `feat/auth-role` - 角色选择登录改造

- **范围**：小程序新增角色选择页；后端 wx-login 支持 `admin` 角色 + 管理员 openid 预设绑定；退出重选机制；`@AdminGuard`。
- **涉及文件**：`apps/user-miniprogram/pages/role-select/`（新）、`apps/user-miniprogram/app.ts`（启动路由：无 token 进角色选择）、`apps/user-miniprogram/utils/auth.ts`（登录带 role、退出重选）；`apps/server/src/modules/auth/{auth.controller,auth.service,auth.module}.ts`、`dto/wx-login.dto.ts`（role 加 admin）、`admin.guard.ts`（新）；`prisma/schema.prisma`（AdminUser +openid）、`prisma/seed.ts`（管理员 openid 种子）。
- **API**：飞书 §4.1 `POST /auth/wx-login` body `{ code, role: 'user'|'merchant'|'admin' }`；§4.3 管理端（改为微信登录 + openid 绑定，原账号密码作废）。
- **数据模型**：新增 `UserRole`（userId + role 唯一，存用户拥有的角色集合）；去掉 `User.role` 单值字段；`AdminUser` 加 `openid String? @unique @map("openid")`；wx-login DTO role 加 `admin`。首次登录自动加 USER 角色；商家角色由 Merchant APPROVED 时加；管理员由 AdminUser.openid 绑定时加。
- **依赖**：auth（已就绪）。
- **暴露契约**：`POST /auth/wx-login` 接受 user/merchant/admin 角色，校验 `UserRole` 拥有；token 载荷带 `role`（当前角色）；`@AdminGuard` 供 admin 接口用；`POST /auth/switch-role`（静默切换，内部即 wx-login 带 newRole）。
- **完成标准**：typecheck + smoke(mock)：选已拥有角色登录成功；选管理员--未绑定 openid 返 `10003`、绑定返 admin token；**静默切换角色**（wx.login + wx-login(newRole) 拿新 token，不退出微信）；admin 接口 `@AdminGuard` 拦非 admin；`UserRole` 多角色并存。
- **隐患**：管理员 openid 种子需用户提供真实 openid（或先用 mock openid 调试）；去掉 `User.role` 需改 `auth.service` 的 `issueTokens`（用登录传入 role 而非 `user.role`）；`UserRole` 表需迁移；切换角色后旧 token 不失效（短期 token 可接受，如需可加黑名单）。

### 2.2 `feat/chat` - MobileIMSDK 接入

- **范围**：部署 MobileIMSDK Server（Node 版，独立容器）；NestJS chat 模块封装 IM 账号/凭证签发 + 消息历史存储；小程序端引入 MobileIMSDK 小程序 SDK（纯 JS，复制文件）+ im-manager 封装。
- **涉及文件**：`apps/server/src/modules/chat/{chat.controller,chat.service,chat.module}.ts` + dto；`apps/server/src/modules/chat/im/`（与 MobileIMSDK 服务端交互的客户端）；`apps/user-miniprogram/libs/mobileimsdk/`（SDK JS 文件）、`services/im.ts`（im-manager 封装）；`docker-compose.yml`（加 mobileimsdk-server 服务）；`docs/开发记录/`（部署说明）。
- **API**：`POST /chat/token`（登录后换 IM 登录凭证：loginUserId + loginToken + wsUrl）、`GET /chat/messages?peerId=&cursor=`（历史消息，NestJS 自存）、`GET /chat/sessions`（会话列表）。
- **数据模型**：新增 `ChatMessage`（id/fromId/toId/content/createdAt，**树洞匿名会话 fromId/toId 用 anonId，不存 uid**）、`ChatSession`（或复用 ChatMatch）。MobileIMSDK 服务端自身另有存储，NestJS 侧只存业务索引/历史。
- **依赖**：auth-role（uid/anonId + token）。
- **暴露契约**：`TimService` 改名 `ImService`（签发 IM loginToken）；`POST /chat/token` 供小程序 loginImpl 用；树洞/兼职沟通消费。
- **完成标准**：typecheck + smoke(mock)：MobileIMSDK 服务端起来 -> 小程序 loginImpl 连接成功 -> 两端 1v1 收发消息 -> 历史消息接口可查；缺凭证/服务端未起时 dev mock + 告警。
- **隐患**：MobileIMSDK 服务端独立进程，部署多一个容器；消息存储双份（MobileIMSDK 自存 + NestJS 业务侧），需对账；小程序 WebSocket 需备案域名 + TLS（测试关域名校验）；匿名会话必须保证 ChatMessage 不落 uid。

### 2.6 `feat/treehole` - 树洞匿名动态 + 匹配 + MobileIMSDK 匿名聊

## 4. 分支协同契约（跨分支读写约定）

| 写方 | 读/写 | 对方表/接口 | 约定 |
|-|-|-|-|
| `feat/auth-role` | 写 | `UserRole`、`AdminUser.openid` | 多角色集合 + 管理员 openid 绑定；登录校验拥有角色 |
| `feat/job` | 写 | `JobPost` 草稿(PENDING) | 草稿由 job 创建 |
| `feat/payment` | 写 | `JobPost.status`->PUBLISHED + `expireAt` | 回调验签后幂等置位 |
| `feat/cron-deploy` | 写 | `JobPost.status`->EXPIRED | 扫 PUBLISHED+expireAt<now |
| `feat/admin` | 写 | 各内容表 status + `ModerationRecord` | 审核「拒绝」回写 REJECTED |
| `feat/merchant` | 读 | `Merchant.status` | job 发岗前校验 APPROVED |
| `feat/chat` | 提供 | `ImService` + `POST /chat/token` | treehole/job 站内沟通消费；`ChatMessage` 树洞用 anonId |
| `feat/treehole` | 隔离 | `AnonymousProfile`↔`User`、`ChatMessage` | **真实 uid 仅后台可追溯；前台/匿名 token/ChatMessage 0 暴露** |

> 跨分支写同一张表（JobPost 被 job/payment/cron/admin 写）时，各写不同 status 流转分支，互不重叠。

## 6. 工作流与测试门槛（每条分支）

1. **切分支**：`git checkout main && git pull && git checkout -b feat/<name>`。
2. **开发**：按本 brief + 飞书契约实现；mock 策略沿用（缺凭证 dev mock、prod 抛 90003）。
3. **本地测试门槛（必须全过才能合并）**：
   - `pnpm -C apps/server run typecheck` + `npx tsc --noEmit`（小程序）通过；
   - 端到端 smoke（mock 模式）跑通核心链路；
   - 关键单测（状态机/防重/匿名隔离/角色鉴权等 P0 逻辑）；
   - 涉及 schema：`prisma migrate dev` 成功 + 必要时 `prisma db seed`。
4. **同步改动记录**：`docs/开发记录/改动记录.md` 顶部追加一条（字段顺序固定，格式与现有一致），状态先「待检查」。
5. **空上下文独立测试**：Agent 工具开空上下文子代理跑 typecheck + smoke + 单测，主代理不得自证。
6. **合并**：`git checkout main && git merge --squash feat/<name> && git commit`（Conventional Commits，中文 subject，结尾 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`）；状态改「已审查」+ 回填 hash；`git push origin main`（网络不稳多重试）。
7. **通知**：合并后告知其他分支 rebase main。

## 7. 风险与注意事项

- **IM 变更风险**：MobileIMSDK 服务端独立部署，多一个容器；消息存储双份需对账；小程序 WebSocket 需备案域名 + TLS（测试关域名校验）。原 TIM 相关代码/配置全删（`.env` 的 `TIM_SDK_APP_ID`/`TIM_SECRET_KEY` 改为 MobileIMSDK 服务端地址 `MOBILEIMSDK_WS_URL` 等）。
- **三端合一风险**：单小程序承载三角色，包体积/页面数增长；角色路由要清晰（角色不符的页面不可进）；admin 页面在小程序里操作体验受限。
- **管理员授权**：openid 预设绑定是安全关键--`AdminUser.openid` 唯一，admin 登录严格校验；种子需用户提供真实 openid。
- **GitHub 推送不稳**：本机到 github.com:443 频繁超时/重置；合并后推送多重试或用户 `! git push`。
- **匿名隔离红线**：treehole + chat 的 ChatMessage 必须保证 0 真实 uid。
- **行尾**：Windows LF/CRLF 警告，建议加 `.gitattributes`。
