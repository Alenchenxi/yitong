## 2. 后端 union feed 接口

### 2.1 接口契约

| 项 | 规格 |
|---|---|
| URL | `GET /api/v1/square/feed` |
| 路径前缀 | `/api/v1`（全局前缀，控制器不需关心） |
| 鉴权 Guard | `@UseGuards(JwtAuthGuard)` 必须；anon token 通过 header 自识别（见 §2.5） |
| Query 参数 | `sort` ∈ {`recommend`, `latest`}，默认 `recommend`；`cursor` 可选；`limit` ∈ [1, 50]，默认 20 |
| 响应 | `200 OK`，body 形如 `{ code: 0, data: FeedResult<FeedItemVo>, message: 'ok' }` |
| 错误码 | `40000` sort 白名单外 / `10001` 未登录 / `50000` 服务器异常 |
| 缓存 | 首屏（无 cursor）且 limit ≤ 20 走 5 分钟内存缓存（与 confession.feed 一致），key 含 `square:${uid}:${anonId ? anonId : 'none'}:${limit}:${sort}` |

### 2.2 响应结构

### 2.3 union 算法

```ts
// apps/server/src/modules/square/square.service.ts (新)
async feed(uid: string, anonId: string | null, q: FeedQueryDto): Promise<FeedResult> {
  const limit = q.limit ?? 20;
  const sort = q.sort ?? 'recommend';
  const fetchSize = limit * 2; // 双倍页大小以覆盖排序分页

  // 1. 并行拉取（不 await 串行，提性能）
  const [posts, anonPosts] = await Promise.all([
    this.fetchApprovedPosts(uid, sort, fetchSize, q.cursor),
    this.fetchApprovedAnonPosts(anonId, sort, fetchSize, q.cursor),
  ]);

  // 2. 合并 + 按 createdAt 降序
  const merged: FeedItemVo[] = [
    ...posts.map((p) => ({ kind: 'post' as const, data: this.toPostVo(p, uid) })),
    ...anonPosts.map((p) => ({
      kind: 'anon_post' as const,
      data: this.toAnonPostVo(p, anonId), // anonId=null 时 liked 不返回
    })),
  ];
  merged.sort((a, b) => b.data.createdAt.localeCompare(a.data.createdAt));

  // 3. 取 limit 条 + 算 nextCursor
  const slice = merged.slice(0, limit);
  const last = slice[slice.length - 1];
  const nextCursor = merged.length > limit && last
    ? Buffer.from(`${last.data.createdAt}|${last.data.id}`).toString('base64')
    : null;
  return { list: slice, nextCursor, hasMore: merged.length > limit };
}
```

要点：
- 拉取 `fetchSize = limit * 2`，确保覆盖穿插排序后的真实 limit
- cursor 解码：`{createdAt, id}` 双字段，查询时 `WHERE createdAt < cursor.createdAt OR (createdAt = cursor.createdAt AND id < cursor.id)`
- 两个 PostVo 复用 confession 的 `toPostVo`，AnonPostVo 复用 treehole 的 `toAnonPostVo`
- 不做"分页后再 merge"——fetchSize 取双倍，merge 后切片；简单可靠
- 性能预期：双查并行 + 内存排序，P95 < 300ms（T6 smoke 验证）

### 2.4 Post 部分查询（fetchApprovedPosts）

复用现有 confession.service 的查询模式，不直接复用 `feed()` 因为它已封装了 FeedResult：

```ts
private async fetchApprovedPosts(uid: string, sort: 'recommend' | 'latest', fetchSize: number, cursor?: string) {
  const cursorWhere = parseCursor(cursor); // 解析双字段 cursor
  const baseWhere: Prisma.PostWhereInput = {
    status: PostStatus.APPROVED,
    visibility: PostVisibility.PUBLIC,
    deletedAt: null,
    ...(cursorWhere ? { OR: [{ createdAt: { lt: cursorWhere.createdAt } }, { createdAt: cursorWhere.createdAt, id: { lt: cursorWhere.id } }] } : {}),
  };
  const orderBy = sort === 'recommend'
    ? [{ featured: 'desc' as const }, { pinned: 'desc' as const }, { likeCount: 'desc' as const }, { createdAt: 'desc' as const }]
    : [{ createdAt: 'desc' as const }, { id: 'desc' as const }];
  return this.prisma.post.findMany({
    where: baseWhere,
    orderBy,
    take: fetchSize,
    include: { author: true /* 拿昵称头像 */ },
  });
}
```

注：confession.feed 已有完整实现含缓存、分页、liked 查询，本接口**不直接复用** `feed()` 但**借鉴其查询模式**——原因是 union 需要 fetchSize 自由控制 + cursor 双字段解析。封装为 `fetchApprovedPosts` 独立方法便于单测。

### 2.5 AnonymousPost 部分查询（fetchApprovedAnonPosts）

复用 treehole.service.listPosts 的 AnonBlock 屏蔽逻辑：

```ts
private async fetchApprovedAnonPosts(anonId: string | null, sort, fetchSize, cursor?) {
  if (!anonId) {
    // anonToken 缺失：仍返回匿名帖（保证时间线可读），liked 字段全部 false
    // 不计算 AnonBlock（无当前用户身份）
  }
  const baseWhere: Prisma.AnonymousPostWhereInput = { status: PostStatus.APPROVED };
  if (anonId) {
    const blockedPeers = await this.treeholeService.getBlockedPeerSet(anonId);
    if (blockedPeers.size > 0) baseWhere.anonId = { notIn: [...blockedPeers] };
  }
  // cursor 解析同 §2.4
  const orderBy = sort === 'recommend'
    ? [{ likeCount: 'desc' as const }, { createdAt: 'desc' as const }, { id: 'desc' as const }]
    : [{ createdAt: 'desc' as const }, { id: 'desc' as const }];
  return this.prisma.anonymousPost.findMany({ where: baseWhere, orderBy, take: fetchSize });
}
```

要点：
- 复用 `treehole.service.getBlockedPeerSet(anonId)`（已存在，P0-16）
- anonId 缺失时 `where.anonId = {}` 不限制（但 liked 全部 false）

### 2.6 鉴权适配（双 token）

**挑战**：现有 Guard 是单 token 设计。NestJS Guard 不能"两个 Guard 串联"——一个用 JwtAuthGuard 强制 access token，另一个用 AnonGuard 强制 anon token。本场景需要：
- access token 必须（保证 uid 用于 Post 部分 liked 查询）
- anon token 可选（缺失时匿名帖 liked 字段不返回，AnOnBlock 不计算）

**方案**：
```ts
@UseGuards(JwtAuthGuard)  // 强制 access token
@Controller('square')
export class SquareController {
  @Get('feed')
  async feed(@Req() req: Request, @Query() q: FeedQueryDto) {
    const uid = (req as AuthenticatedRequest).user!.uid;
    const anonId = extractAnonIdFromHeader(req); // 见下
    return ok(await this.square.feed(uid, anonId, q));
  }
}
```

`extractAnonIdFromHeader` 实现思路：
- 从 header `authorization` 中读取 token
- 如果是 access token（同 JwtAuthGuard 注入的用户就是 access token 用户），则 anonId 为 null
- 实际上 anon token 与 access token 共用同一个 `Authorization: Bearer xxx` header 但 token 内容不同（payload: `{uid, type}` vs `{anonId, type:'anon'}`）

**实现**：
```ts
function extractAnonId(req: Request): string | null {
  const auth = req.headers.authorization;
  if (!auth?.startsWith('Bearer ')) return null;
  const token = auth.slice(7);
  try {
    const payload = jwt.verify(token, secret) as JwtPayload;
    return payload.type === 'anon' ? payload.anonId : null;
  } catch {
    return null;
  }
}
```

但这又涉及双 token 鉴权——需要识别同一个 Authorization 头但 payload 不同。这与"用 AnonGuard 强制 anon token"是不同的场景。

**简化方案**：square controller 只用 JwtAuthGuard（强制 access token）。anonId 通过单独的查询参数 `?anonToken=xxx` 传递（HTTP 不推荐 query 带 token，但匿名 token 可接受；或通过 body）。前端在 anonRequest 已有的 Authorization 头之外，再单独传一份。

**最终方案**：用 NestJS 装饰器从 Authorization 头二次解析：

```ts
// apps/server/src/common/auth/anon-from-header.decorator.ts (新)
export const AnonIdFromHeader = createParamDecorator((data: unknown, ctx: ExecutionContext): string | null => {
  const req = ctx.switchToHttp().getRequest<Request>();
  const auth = req.headers.authorization;
  if (!auth?.startsWith('Bearer ')) return null;
  const token = auth.slice(7);
  try {
    const payload = jwtService.verify(token) as any;
    return payload.type === 'anon' ? payload.anonId : null;
  } catch {
    return null;
  }
});
```

controller 端：
```ts
@Get('feed')
async feed(
  @Req() req: Request,
  @Query() q: FeedQueryDto,
  @AnonIdFromHeader() anonId: string | null,
) {
  const uid = (req as AuthenticatedRequest).user!.uid;
  return ok(await this.square.feed(uid, anonId, q));
}
```

注意：当前 AnonGuard 也是从 Authorization 头取 token。JwtAuthGuard 优先匹配（因为 access token 永远有），anonId 仅在 token 是 anon 类型时返回。本方案可工作。

**现状**（apps/user-miniprogram/services/treehole.ts L55-71）：
- `anonToken` / `anonId` 是模块级变量，模块加载时为 `''`

- `GET /treehole/posts?sort=latest|recommend&mood=` —— 树洞原有广场列表

- `POST /treehole/posts/:id/like` —— 树洞点赞（anonToken）
- `POST /posts/:id/like` —— 表白墙点赞（accessToken）
- `GET /announcements` —— 公告
- 表白墙关注/粉丝/搜索/草稿/私密 等接口

### 7.2 不破坏的入口
- 表白墙 tab（左二）：4 tab 完整不变
- 树洞首页：匿名身份 + 群聊广场入口 + 匹配入口
- 树洞群聊广场（P2-07）：3 排序 + tag 筛选 + isMember

### 7.3 边界情况
| 场景 | 预期 |
|---|---|
| 用户无 access token | 401（JwtAuthGuard 拒） |
| 用户有 access token 无 anon token | union 返回仅表白墙帖（按 anonBlock 排除对端匿名帖）；匿名帖 liked 全部 false；前端点赞/评论 disabled |
| 用户匿名态发帖后立即看推荐 | union 应能返回自己的匿名帖（不自我屏蔽：AnonBlock 不影响自己） |
| AnonBlock 双向屏蔽对端 | union 列表排除对端匿名帖 |
| 表白墙帖 deletedAt 非空 | union 排除（baseWhere deletedAt: null） |
| AnonymousPost status 非 APPROVED | union 排除（baseWhere status: APPROVED） |
| 游标分页跨类型 | cursor 编码 `createdAt\|id`，双字段游标防重复/漏读 |
| 拉取双倍页大小后 | merged.length > limit 才设置 nextCursor，避免多读少返 |
| 同分钟并发发帖 | 按 createdAt desc 排，可能两个相邻 PostVo 但分页游标 id 兜底 |

### 8.1 RED 阶段必写失败的 smoke 场景

文件：`apps/server/scripts/smoke-square-hybrid-contract.mjs`

覆盖场景（与原 Jest 14 个 it 一一对应）：

```js
// 1. union 基础
contract('GET /square/feed?sort=recommend returns mixed post + anon_post')
contract('GET /square/feed?sort=latest returns sorted by createdAt desc')

// 2. sort 白名单
contract('GET /square/feed?sort=follow returns 400')
contract('GET /square/feed without sort defaults to recommend')

// 3. 双 token 鉴权
contract('anon post liked=false when anonToken missing')
contract('anon post liked reflects AnonPostLike when anonToken present')
contract('GET /square/feed without access token returns 401')

// 4. AnonBlock 屏蔽隔离
contract('blocked peer anon_post excluded when anonToken present')
contract('blocked NOT computed when anonToken missing (all anon posts visible)')

// 5. 红线断言
contract('anon_post kind NEVER contains authorId/authorNickname/authorAvatarUrl')
contract('anon_post kind NEVER contains UserId/uid')

// 6. 分页
contract('returns nextCursor when more items available')
contract('returns nextCursor=null when no more items')
contract('respects cursor parameter for pagination')

// 7. 数据过滤
contract('excludes post with deletedAt != null')
contract('excludes post with visibility != PUBLIC')
contract('excludes anon_post with status != APPROVED')

// 8. fetchSize 边界
contract('fetches fetchSize = limit * 2 from each source')
contract('merges and slices to limit items')
```

每个 contract 是一条独立 fetch + 断言（与现有 smoke 一致：失败立即退出非 0）。
