## 一、需求与背景

用户要求：**表白墙、树洞都要能够评论、转发，并且能够看到浏览数、评论数、点赞数；转发是转发给微信好友。**

改造前现状：
- **表白墙**已有完整评论（`Comment` + `CommentLike`、`post-detail` 页评论区/回复/输入条/评论点赞），`PostVo` 已有动态 `commentCount`（`_count`）。
- **树洞**完全没有评论（无模型、无端点、无 UI），仅 `likeCount` + `AnonPostLike`。
- **两端都无浏览数**（`Post`/`AnonymousPost` 无 viewCount）。
- **两端都无转发**（全小程序仅 referral / job 详情页有 `onShareAppMessage`）。

## 二、已确认决策

| 决策点 | 结论 |
|---|---|
| 浏览数口径 | 加 `viewCount` 标量，详情接口 fire-and-forget 自增；**不用** ContentView（「今日上头」去重口径留给圈子计划，两者并存不混用） |
| 树洞评论身份 | 匿名，评论者身份 = `anonId`，区分**楼主**（`isLZ = authorAnonId === post.anonId`） |
| 转发范围 | 详情页 + 列表卡片都可转发给微信好友 |
| 评论结构 | 平铺无回复 thread，`createdAt desc` 最新优先，`commentCount` 动态 `_count` |

## 三、交付内容

### 3.1 数据模型（迁移 `20260812090000_anon_comment_viewcount`，ADD-only）

- `Post` 加 `viewCount Int @default(0) @map("view_count")`（累计浏览数 PV）。
- `AnonymousPost` 加 `viewCount` 标量 + `comments AnonComment[]` 关系。
- 新模型 `AnonComment`：`id / postId / anonId / content / likeCount / createdAt`，`@@index([postId, createdAt])`。
- 新模型 `AnonCommentLike`：`commentId / anonId` 唯一，`@@unique([commentId, anonId])`，`onDelete: Cascade`。
- **红线**：`anon_comments` / `anon_comment_likes` 0 处真实 uid（仅 `AnonymousProfile` 后台可追溯）；不 FK 到 `AnonymousProfile`（与 `AnonPostLike`/`AnonBlock` 一致，`rotateUnsafeAnonId` 批量 updateMany 不用多张表）。

### 3.2 后端接口（路由前缀 `/api/v1`）

**树洞评论**（`@Public() + @UseGuards(AnonGuard)`，`Authorization: Bearer <anonToken>`，`req.user.uid = anonId`）：

| 端点 | 方法 | 限流 | 入参 | 返回 | 错误码 |
|---|---|---|---|---|---|
| `/treehole/posts/:id/comments` | POST | 5/min | `{ content: string(1-500) }` | `AnonCommentVo` | 40001 帖不存在 / 30005 双向屏蔽 / 90002 checkText |
| `/treehole/posts/:id/comments` | GET | — | `page, pageSize`（默认 1,20） | `PageResult<AnonCommentVo>` | 40001 / 30005 |
| `/treehole/comments/:id/like` | POST | 10/min | — | `{ liked, likeCount }` | 30010 评论不存在 |

`AnonCommentVo`：`{ id, postId, authorAnonId, content, likeCount, liked, isLZ, createdAt }`

**浏览数自增**（fire-and-forget，镜像 job.controller 模式）：
- `GET /posts/:id`（表白墙）响应含 `viewCount`，每次访问 +1
- `GET /treehole/posts/:id`（树洞）响应含 `viewCount` + `commentCount`，每次访问 +1
- VO 加字段：`PostVo.viewCount`、`AnonPostVo.viewCount + commentCount`

**square.service.ts 类型对齐**：`toPostVo`/`toAnonPostVo` 加 `viewCount`/`commentCount`/`_count`（与圈子计划按 ADD 并集）。

## 七、潜在隐患

1. 树洞评论无回复 thread / 无删除 / 无举报 / 无通知（树洞匿名作者通知不做）——本期范围外。
2. 转发落地不做 channel 上报统计；分享卡片 title 取 content 前 20 字。
3. `viewCount` 口径为「详情访问累计」，与圈子「今日上头」ContentView 去重口径并存，勿混用。
4. 评论 VO 的 `liked` 依赖 AnonGuard 的 anonId（与帖子点赞同机制）；`rotateUnsafeAnonId` 匿名轮换会清空评论点赞（与帖子点赞行为一致）。
5. 树洞详情无 anonToken 时引导初始化，不再静默签发（行为变更，符合预期）。
