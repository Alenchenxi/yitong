# 广场混合流 — 增量任务计划 (CR-001)

> 本文档为广场 tab（P1-29 已完成）的增量变更计划。背景：用户决定将广场从「表白墙精简入口」升级为跨模块混合流入口，合并展示表白墙公开帖 + 树洞个人匿名动态（不含群聊广场、不含群聊帖），主 tab 为「推荐 / 最新」。本计划仅覆盖增量任务，不重复 P1-29 已交付的 tabBar / 启动路由 / service 封装。
>
> 对应基线文档更新：
> - docs/功能规划.md §0 + §1.8（CR-001）
> - docs/UI设计规范.md §9.0（CR-001）
> - docs/任务规划.md §3 P1-30 + §10 变更日志（CR-001）

## 1. 范围与约束

### 1.1 范围
- **新增**：广场推荐 / 最新 tab 返回表白墙帖 + 个人匿名帖（AnonymousPost）混合流
- **新增**：广场前端支持匿名卡降级渲染（去头像/昵称，显示「匿名」+ mood）
- **新增**：anonToken 缺失时匿名帖点赞 / 评论按钮 disabled + 提示原因
- **新增**：后端 `/square/feed` union 接口（access token + anon token 双鉴权）
- **保留**：表白墙 tab（左二）4 tab 完整入口不变；树洞首页（匿名身份 + 群聊广场入口 + 匹配入口）不变；树洞群聊广场不变

### 1.2 约束（不可破）
- **树洞匿名红线**：AnonymousPost 表 0 uid、anonToken 不含真实 uid、union FeedItemVo 严禁回填真实身份字段
- **AnonBlock 隔离延续**：广场 union 列表必须排除与当前用户 anonId 双向屏蔽的对端匿名帖
- **匿名卡视觉降级**：不显示真实头像/昵称，显示「匿名」标识 + 匿名昵称 + mood（可选）
- **关注 tab 移除**：匿名帖无 follow 语义，广场下不暴露关注流（关注行为仍在表白墙完整入口）

### 1.3 不在范围（防范围蔓延）
- 群聊广场（AnonGroup）合入（保留独立入口）
- 群聊内帖合入（保留群聊独立消息流）
- 匿名帖关注/收藏功能（树洞匿名本身无关系链）
- 树洞首页结构调整（仅复用其匿名签发入口做 anonToken 引导）

## 2. 验收标准 (AC)

按 docs/功能规划.md §1.8 CR-001 新增条款，验收标准如下：

### AC-1：推荐 tab 返回混合流
- **Given** 用户登录且访问广场推荐 tab
- **When** 调用 `/square/feed?sort=recommend`
- **Then** 返回表白墙帖（PostVo）与匿名帖（AnonymousPostVo）按 createdAt 降序穿插的混合列表，每页 20 条
- **And** 匿名帖卡片不显示真实头像/昵称，显示「匿名」标识 + 匿名昵称 + mood（如有）

### AC-2：最新 tab 返回混合流
- **Given** 用户访问广场最新 tab
- **When** 调用 `/square/feed?sort=latest`
- **Then** 返回按 createdAt 降序的混合列表（仅按时间排序，不做热度）
- **And** 支持 cursor 分页，与原 confession feed 一致体验

### AC-3：关注 tab 不在广场
- **Given** 用户访问广场
- **When** 渲染主 tab
- **Then** 仅展示「推荐 / 最新」2 个 tab，无「关注」tab

### AC-4：匿名帖卡片点击跳树洞详情
- **Given** 列表中存在匿名帖卡片
- **When** 用户点击卡片
- **Then** 跳 `/pages/treehole/post-detail/index?id={postId}`，不跳表白墙详情页

### AC-5：匿名帖点赞走 anonToken 路径
- **Given** 用户已签发 anonToken（树洞匿名身份激活）
- **When** 点击匿名帖点赞按钮
- **Then** 请求带 anonToken Authorization 头调 `/treehole/posts/:id/like`（独立 endpoint，独立 storage）
- **And** 不影响表白墙 uid 点赞状态
- **And** 返回后匿名帖 likeCount / liked 字段更新

### AC-6：anonToken 缺失时匿名帖仍展示但点赞/评论 disabled
- **Given** 用户未签发 anonToken（未访问过树洞）
- **When** 浏览广场列表
- **Then** 匿名帖仍正常展示（保证时间线可读）
- **And** 匿名卡点赞按钮 disabled（透明度 0.5）
- **And** 点击 disabled 按钮弹出 toast「请前往树洞签发匿名身份后互动」
- **And** 评论按钮同样 disabled 行为
- **And** 表白墙帖点赞/评论不受 anonToken 状态影响

### AC-7：表白墙入口（左二）数据源/行为不变
- **Given** 用户点击表白墙 tab
- **When** 浏览表白墙首页
- **Then** 仍展示关注/推荐/最新/热门 4 tab，数据源为 `/posts/feed`
- **And** 运营位（最热/今日上头/活动专题/校园话题）保持不变
- **And** 启动 user 角色默认落广场的行为不变

## 3. 技术方案

### 3.1 后端 union feed

**新接口**：`GET /api/v1/square/feed?sort=recommend|latest&cursor={...}&limit={...}`

**鉴权**（双 token）：
- access token（表白墙 uid）—— 必须，Post 部分需要 uid 鉴权（关注状态等扩展预留）
- anon token（树洞 anonId）—— 可选；缺失时匿名帖仍返回但不返回 liked 状态，点赞接口拒绝

**实现策略**：
- 后端新增 `apps/server/src/modules/square/` 模块
  - `square.controller.ts`：定义 `GET /feed` 接口
  - `square.service.ts`：union PostVo + AnonymousPostVo
  - DTO 与原 confession/feed 一致，扩展 sort 参数白名单（仅 allow `recommend` / `latest`）
- union 算法：
  - 拆查：分别从 Post（visibility=PUBLIC，deletedAt null）和 AnonymousPost 拉取 sort 对应规则（recommend 用热度+时间，latest 按 createdAt）各 2 倍页大小
  - 合并：按 createdAt 降序 merge 取 limit 条
  - 映射：分别映射成统一 `FeedItemVo`（discriminator: `kind: 'post' | 'anon_post'`）
- 鉴权适配：
  - controller 同时识别 access token（JwtAuthGuard）+ anon token（AnonGuard）
  - 缺失 anon token 时 AnonymousPostVo.liked 字段不返回（false + 点赞接口拒绝）
- 屏蔽隔离：union 时调用现有 `AnonBlock` 排除双向屏蔽对端匿名帖（沿用 P0-16）
- 0 数据库改动：AnonymousPost / Post / AnonBlock 已存在

### 3.2 前端 union feed + 匿名卡降级

**前端结构**：
- `apps/user-miniprogram/services/square.ts`（新）：union feed service，封装 `/square/feed`
- `apps/user-miniprogram/pages/square/index.ts`（重构）：调 union 接口，关注 tab 改为推荐/最新
- `apps/user-miniprogram/components/post-card/`（扩展）：
  - 新增 `anonymous` prop 控制匿名降级渲染
  - 头像区改匿名 emoji 占位 + 「匿名」标签 + 匿名昵称
  - 点赞/评论按钮接受 `disabled` prop + 提示文本
- `apps/user-miniprogram/utils/auth.ts`（扩展）：
  - anonToken 生命周期管理（拉取/存储/过期清理）
  - 与 access token 并存于 globalData + storage
- `apps/user-miniprogram/services/treehole.ts`（复用）：
  - 复用 `signAnonToken()` 给登录用户补签 anonToken（如未签发）

**anonToken 缺失体验**：
- 全局 anonToken 状态从 globalData 读
- 匿名卡渲染时 anonToken 缺失 → 点赞/评论按钮 disabled + 点击 toast
- 引导：toast 文案「请前往树洞签发匿名身份后互动」，本期不做「点此前往」跳转按钮，留 TODO

### 3.3 类型定义

**packages/shared-types**（如已有）：扩展 `FeedItemVo`：
```ts
export type FeedItemVo =
  | { kind: 'post'; data: PostVo }
  | { kind: 'anon_post'; data: AnonymousPostVo };
```

如果 shared-types 未定义 AnonymousPostVo，需同步添加。
