1. **内容安全 fail-open**：msgSecCheck/imgSecCheck 接口故障或网络抖动时选择放行 + 告警，违规内容可能漏过；生产应改为可配置 fail-open/fail-closed 或失败转人工审核队列。

8. **无文件类型深度校验**：仅按 mimetype 判断，未校验文件魔数；可伪造 mimetype 上传非图片。

### 修改文件
- `apps/server/src/modules/auth/auth.service.ts` — ① code2session URL `jsauth2`→`jscode2session`（严重：生产环境微信登录 100% 失败）；② fetch 增加 10s 超时 + `res.ok` 检查 + 网络异常兜底；③ access/refresh token 签发时加 `type` 字段，refresh 校验仅放行 `type==='refresh'`；④ `getMe` 中 `401 as unknown as HttpStatus` 改为 `HttpStatus.UNAUTHORIZED`；⑤ upsert 补注释说明 role 设计意图
- `apps/server/src/modules/auth/auth.controller.ts` — `me` 防御性抛错状态码 400→401（`HttpStatus.UNAUTHORIZED`），补 import

- `apps/server/src/modules/auth/jwt-auth.guard.ts` — 守卫校验仅放行 `type==='access'`，拒绝 refresh token 互换访问
- `apps/server/src/modules/auth/auth.module.ts` — 生产环境缺失 `JWT_SECRET` 时抛错，不再静默回退硬编码弱密钥

### 完成的工作
- ✅ 修复 code2session URL 拼写错误（`jsauth2`→`jscode2session`），生产环境微信登录可正常调用
- ✅ access/refresh token 增加 `type` 字段并双向校验，堵住互换漏洞（access 不能刷新、refresh 不能直接访问接口）
- ✅ fetch 增加超时（10s）、HTTP 状态码检查、网络异常 try/catch 兜底
- ✅ 统一所有鉴权相关异常的 HTTP 状态码为 401（`getMe`、`me` 防御性抛错）
- ✅ 生产环境 `JWT_SECRET` 缺失时启动即报错，避免弱密钥风险
- ✅ upsert 补注释明确「role 仅选 AppID，用户角色默认 USER，商家身份走 Merchant 表」
- typecheck（`tsc --noEmit`）通过

### 潜在隐患
1. **mock 仍掩盖真实路径**：开发环境未配凭证时走 mock，code2session 真实路径仍需配真实凭证后才能验证（本次 URL 修复即因此被 mock 掩盖，开发阶段完全暴露不出）。
2. **token 共用 secret 未分离**：本次仅加了 `type` 区分，access/refresh 仍共用 `JWT_SECRET`；生产应分离 `JWT_REFRESH_SECRET` + 服务端存 refresh 记录支持吊销（沿用上一条隐患，未完全解决）。
3. **未运行时验证**：仅 typecheck 通过，真实 code2session 调用需配 WX 凭证 + PostgreSQL 后验证。
4. **AbortSignal.timeout 兼容性**：依赖 Node 18+ 全局 `AbortSignal.timeout`；若运行时低于 Node 18 需改用 `AbortController` + `setTimeout`。

### 后续待做工作 / 方向
1. 运行时验证：配真实 WX 凭证后 curl 打通 wx-login/refresh/me，确认 code2session URL 修复生效。

- `apps/server/src/modules/auth/jwt-auth.guard.ts` — 全局 JWT 守卫
- `apps/server/src/modules/auth/dto/wx-login.dto.ts` — 登录 DTO（code/role/nickname?/avatarUrl?）
- `apps/server/src/modules/auth/dto/refresh-token.dto.ts` — 刷新 DTO
- `apps/server/src/modules/auth/auth.service.ts` — code2session + upsert + 签发/校验 token
- `apps/server/src/modules/auth/auth.controller.ts` — wx-login / refresh / me
- `apps/server/src/modules/auth/auth.module.ts` — 装配（全局 JwtModule）

### 修改文件
- `apps/server/src/common/filters/all-exceptions.filter.ts` — 兼容 class-validator 数组消息（join `'; '`）
- `apps/server/src/app.module.ts` — 接入 AuthModule，注册 `APP_GUARD = JwtAuthGuard`

### 完成的工作
- `POST /api/v1/auth/wx-login`：role 选 AppID → code2session → upsert User → 签发 access(2h)/refresh(7d)
- `POST /api/v1/auth/refresh`：校验 refresh → 重发 token
- `GET /api/v1/auth/me`：Bearer → 当前用户
- 全局 JwtAuthGuard：非 `@Public` 接口强制 Bearer，校验失败抛 `10001/10002`
- `BizException` + `AllExceptionsFilter` 统一 `{ code, message, traceId }`
- typecheck（`tsc --noEmit`）通过

### 潜在隐患
1. **token 安全**：access/refresh 共用 `JWT_SECRET`；refresh 泄露可续命 7 天。生产应：分离 refresh secret + 服务端存 refresh 记录支持吊销 + 缩短/轮换 refresh。
2. **mock code2session**：开发环境（`NODE_ENV≠production`）未配 WX 凭证时，**任意 code 都能登录**（返回 `mock_<code>`）。部署前务必：① 配齐 `WX_USER/MERCHANT_APPID/SECRET`；② 设 `NODE_ENV=production`。
3. **无限流**：wx-login/refresh 可被刷，未接限流（路线图 P1）。
4. **无 token 吊销**：用户被封禁后旧 token 仍有效至过期；需黑名单或短期 token + 强制刷新。
5. **用户资料可伪造**：nickname/avatarUrl 由前端传入，未校验真实性。需可信资料时改用 `wx.getUserProfile` 加密数据解密。
6. **无单测**：auth 属 P0 模块但尚未写测试（见开发规范 §10），需补 wxLogin/refresh/guard 单测。
7. **未运行时验证**：仅 typecheck 通过；需 PostgreSQL + 首次 `prisma migrate` 后才能跑通 wx-login。
8. **role 单值**：`User.role` 单字段，同一自然人既为学生又为商家时无法兼表；后续可能改多角色或经 Merchant 关联表达。
9. **code2session 用全局 fetch**：超时/重试未配置；网络抖动可能 5xx。建议加超时与重试。

### 后续待做工作 / 方向
1. **运行时验证**：起 PostgreSQL → 填 `DATABASE_URL` → `pnpm --filter @yitong/server prisma:migrate dev` → curl/Postman 打通 `wx-login / refresh / me`。
2. **接用户端小程序登录**：`wx.login` 拿 code → 调 `/auth/wx-login` → token 存 `globalData` + `wx.setStorageSync` → `/auth/me` 拉资料渲染「我的」。
3. **补单测（P0）**：Jest 写 wxLogin（mock code2session 成功/失败）、refresh（有效/过期/无效）、JwtAuthGuard（@Public 放行 / 无 token / 有效 / 过期）。
4. **生产化 token**：分离 `JWT_REFRESH_SECRET`；服务端存 refresh 记录支持吊销；去掉 mock（`NODE_ENV=production`）。
5. **限流**：`@nestjs/throttler` 对 `wx-login / refresh` 限流（如 5/min/IP）。
6. **token 吊销**：Redis 黑名单或缩短期 + 强制刷新。
7. **内容安全接入**：发帖前调 `msgSecCheck/imgSecCheck`（moderation 模块）。
8. **role 设计评估**：判断是否改多角色或经 Merchant 关联表达「学生+商家」双重身份。
9. **fetch 超时/重试**：或换 `@nestjs/axios` + interceptor。
10. **提交**：开 `feat/auth` 分支提交本模块 + 本改动记录。
